# 示例 40：从用户经验到认知项目

这份方法来自一次真实的情感教练项目构建过程，但它不是情感专用方法，而是通用认知工程方法。

## 核心判断

用户本人必须提供该领域的关键词、关键概念、实际心得、看法和真实场景。AI 不负责凭空制造“领域智慧”，AI 负责把用户的经验密度提纯成结构。

```text
认知项目不是 AI 的知识整理，而是用户的经验体系化。
没有用户自己的关键词和真实场景，AI 做出来的是百科；
有用户自己的心得和痛点，AI 才能做出认知武器。
```

## 演化链路

```text
真实材料 -> 高能心法 -> 判断模型 -> 教练流程 -> 匿名案例 -> Skill 项目
```

更完整：

```text
用户输入领域种子
-> AI 提炼关键词和概念
-> 共同确认核心心法
-> AI 建立模型和分层
-> 用户继续提供真实案例
-> AI 抽象成 case
-> AI 生成教练流程
-> AI 封装成项目
-> 后续持续追加新场景
```

## 用户输入层

用户应该提供：

- 领域名称
- 核心关键词
- 关键概念
- 实际心得
- 真实场景
- 常见误判
- 想解决的问题
- 想长期执行的心法

这些内容越个人、越真实、越有痛感，项目越有价值。

## AI 输出层

AI 应该产出：

- 术语表
- 状态机
- 阶段模型
- 判断表
- 操作手册
- 教练输出模板
- 匿名 case
- skill 项目结构

## 文件结构

推荐结构：

```text
project/
├── README_项目自述与概述.md
├── SKILL_技能说明与使用指南.md
├── SKILL_技能说明中文版.md
├── methodology/
│   └── index.zh-CN.md
├── references/
│   └── module-name.zh-CN.md
└── cases/
    └── case-01-topic.zh-CN.md
```

## 一句总纲

```text
不要从理论开始，要从真实痛点开始；
不要停在感悟，要压成心法；
不要停在心法，要建成模型；
不要停在模型，要做成教练；
不要停在教练，要沉淀案例；
不要停在案例，要封装成可反复调用的 skill。
```
