# Agent 反堆砌与上下文工程原则

很多垂直 agent 的问题不是能力不够，而是把流程复杂度误当成能力增强。

当通用 coding agent 已经足够强时，垂直架构的价值不应是替模型思考，而是给模型提供更适合工作的环境：

```text
干净的上下文
稳定的目标锚点
低成本的环境理解
可持续的外部工作记忆
少污染的工具和子任务边界
```

一句话：

```text
Agent 架构不是让 LLM 变得更忙。
Agent 架构是让 LLM 在正确、干净、稳定、低噪声的环境里思考。
```

## 反堆砌三问

任何新层、新 workflow、新 memory、新 skill、新 multi-agent 设计，在进入主运行链路前必须回答三问：

1. 它是否降低了上下文获取成本？
2. 它是否提升了状态稳定性？
3. 它是否增强了对真实领域环境的理解？

如果三问都答不上来，它不能进入主链路。它只能成为：

- 离线解释。
- 日志字段。
- 回放指标。
- 可选 skill。
- 触发式注意力锚点。
- 后台优化实验。

如果三问答得上来，仍然不要直接塞进 prompt。优先判断它应不应该沉淀为 Skill：重复、可共享、可执行、需要脚本确定性或会降低上下文成本的方法，应该进入 Skill 包，而不是常驻主上下文。

## 折叠后的运行架构

最终架构不要在每轮任务里全量展开。运行时应折叠成三层：

```text
常驻最小内核
+ 按需触发模块
+ 离线进化系统
```

### 1. 常驻最小内核

常驻层只保留五个东西：

```text
Task Envelope
Context Pack
External Working Memory
Execution Loop
Final Sync
```

含义：

- `Task Envelope`：当前目标、验收、边界、风险和输出形式。
- `Context Pack`：本轮最小有效上下文，不把所有 memory、skill、历史都塞进来。
- `External Working Memory`：`task_plan.md`、`progress.md`、`findings.md` 这类外部工作记忆。
- `Execution Loop`：理解、行动、验证、修正。
- `Final Sync`：结果、证据、剩余风险、下一步和可沉淀经验。

这五个是“开机必备”。其他都不是。

### 2. 按需触发模块

以下模块只有在触发条件成立时才进入上下文：

- `T_t` 思维内核：任务需要战略、战术、学习、分析或行动分解时触发。
- `H_t` 人文之光：用户处境、关系、苦难、长期滋养或表达温度重要时触发。
- `L6` 存在统摄：行动会影响价值、风险、系统边界或因果链时触发。
- `I_t` 副本意识法：旧人旧事、旧任务、旧失败或情感回声牵引当前主线时触发。
- skills：当前任务真的需要某个压缩方法时触发。
- tools：当前问题需要现实证据、文件、网页、命令或 API 时触发。
- multi-agent：上下文隔离收益大于协调成本时触发。

这些模块是注意力锚点，不是仪式。

### 3. 离线进化系统

以下模块默认不污染主上下文：

- `Λ-Base`：把日志转为样本。
- `Σ-Loop`：追踪自模型、行动、反馈和自模型更新。
- `Eval / Replay`：验证升级是否真实。
- `万物择优`：从重复 trace 里选择可晋升候选。
- `修炼账本`：记录经验、心魔、境界和成长。
- `审计 / 信任`：离线检查退化、幻觉、越界和信任承载。

它们的职责是让 agent 变强，不是让当前这轮回答变重。

## 外部工作记忆

长任务里，模型最容易漂移的不是智力，而是状态。

所以对复杂任务，优先建立外部工作记忆：

```text
task_plan.md     当前目标、边界、验收和任务拆分
progress.md      已完成、当前阻塞、下一步
findings.md      已确认事实、架构线索、坑和不可重复探索
decision_log.md  关键取舍、原因和后果
```

这些文件不是文档负担，而是 agent 的外部工作记忆。它们让模型不用在长上下文里反复重新认识项目。

## Multi-Agent 使用门槛

multi-agent 的首要价值不是角色扮演，而是上下文隔离。

只有当下面至少一个条件成立，才值得使用：

1. 任务天然高并行：大仓库扫描、批量测试、多 repo 搜索。
2. 上下文必须隔离：搜索、编码、测试、审计互相污染会降低主线程质量。
3. 角色长期存在：数据库、infra、安全策略等长期积累专业上下文。

否则，单 agent 加干净上下文通常更强。

## 架构味道检查

坏味道：

- 每个任务都启动完整脑区、修炼、存在、人文和审计。
- 每个错误都写长期记忆。
- 每个复杂问题都开多 agent。
- skill 触发后输出大量方法论，而不是压缩路径。
- RAG 把无关资料塞进主上下文。
- workflow 让模型忙于走流程，而不是解决主要矛盾。
- skill 把长 prompt 换了个文件名，没有 progressive disclosure、scripts、references 或验证。

好味道：

- 开局上下文很短，但命中目标。
- 长任务有 `task_plan / progress / findings`。
- 子 agent 只返回结论、证据和文件路径，不污染主线程。
- 日志和回放在离线层增长，主链路保持轻。
- 每个架构层都能说明自己降低了哪类认知成本。
- 重复方法被沉淀成可发现、按需加载、可执行、可版本管理的 Skill 包。

## 最小提示

```text
[ANTI-BLOAT CHECK]
- 当前任务常驻五核是否足够？
- 新增层是否降低上下文获取成本、提升状态稳定性或增强环境理解？
- 它应该进入主上下文，还是作为按需 skill / 离线日志 / replay 指标？
- 是否需要外部工作记忆文件来稳定目标？
- multi-agent 的上下文隔离收益是否大于协调成本？
[/ANTI-BLOAT CHECK]
```

这条检查不应该变成用户可见仪式。它应该像呼吸一样，在架构扩张前轻轻挡一下。
