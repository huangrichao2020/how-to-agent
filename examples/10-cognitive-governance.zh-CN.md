# 示例 10：认知治理工作手册

[English](10-cognitive-governance.md) · [简体中文](10-cognitive-governance.zh-CN.md)

当一个 agent runtime 已经有 memory、tools、skills、频道历史和长任务恢复后，继续说“多记一点”往往不再解决问题。这时真正的瓶颈不是存储，而是认知质量。

## 起点

核心洞察很简单：

> 认知是信息摄入、注意力选择、信息处理、联想激活、对外反应、外界反馈和模型更新组成的动态闭环。

一个 agent 会被它接触的信息、保留的痕迹、承认的事实、激活的联想和吸收的反馈塑造。如果这些表面低质量，即使底层模型很强，agent 也会变得嘈杂、跑偏、机械。

目标不是建一个更大的 memory 堆，而是建立一套认知治理系统，持续提高：

- 输入质量
- 注意力质量
- 联想质量
- 反应质量
- 反馈质量
- 长期更新质量

## 这是运行时架构，不是日记功能

在 GA 或 Hermes 里，认知治理应该成为运行时架构，而不是一个小日记插件。日记只是输入面之一。真正的架构要影响每一次频道对话：

```text
输入表面
  -> Purpose 识别
  -> 注意力门控
  -> 上下文组装
  -> 回答 / 行动
  -> 反馈捕获
  -> 准入门
  -> 持久认知更新
```

输入表面包括飞书消息、当天完整飞书群聊、飞书文档、任务日志、工具输出、重启事件、用户主动写下的笔记，以及 L5 日记。它们进入系统时都只是证据。没有任何一种输入可以绕过准入门，直接变成身份、事实或技能。

实用原则是：**写一遍，多路由**。

- 用户写在飞书文档里，agent 就读取文档，而不是要求用户再粘贴。
- 用户说“刚刚讨论的所有内容”，agent 就使用近期会话证据，而不是只看最后一句。
- 材料讲运行方式，可以沉淀成 skill、SOP 或架构笔记。
- 材料讲用户真实生活，可以进入 L5 证据层。
- 材料讲关系感受，可以进入滋养原则。
- 材料只是短时情绪，通常应留在事件证据里，不要永久化。

这样 GA/Hermes 会有一根统一的认知脊柱：所有输入都是证据，Purpose 控制注意力，准入控制持久化，反馈控制未来更新。

## 核心理论

不要只按“存在哪里”划分 agent 状态。要按“它凭什么指导行动”划分。

```text
原始信号
  -> 痕迹
  -> 事件记忆
  -> 候选断言
  -> 权威事实
  -> 可迁移知识
  -> 流程 / 技能
  -> 身份 / 规范
  -> 滋养 / 成长
  -> L5 人类真实行为 / 日记
```

这套工程阶梯可以和 DIKWP 对齐，但不要混为一谈。DIKWP 是语义认知层，关注 Data、Information、Knowledge、Wisdom、Purpose 如何互相转化；本手册的痕迹、事件、断言、事实、知识、流程、身份、滋养和 L5，是 agent runtime 的治理层，关注什么内容有资格影响行动。

## DIKWP 对齐

DIKWP 的 P 应优先理解为 **Purpose（意图/目的）**，不是 Pattern。Pattern 更像是在信息生成和知识抽象过程中出现的模式识别结果。

把 DIKWP 放进 agent 认知治理后，可以这样理解：

| DIKWP | 中文 | 在 agent 中的作用 | 对应治理问题 |
|---|---|---|---|
| Data | 数据 | 原始输入、日志、消息、工具输出、状态快照 | 这是什么信号？可信来源是什么？ |
| Information | 信息 | 被目的筛选后的差异、关联、语义变化 | 当前任务要关注什么差异？ |
| Knowledge | 知识 | 结构化关系、可验证模型、可迁移规则 | 哪些规律能解释和预测？ |
| Wisdom | 智慧 | 结合价值、长期目标、风险和情境后的判断 | 什么选择更合适、更负责任？ |
| Purpose | 意图 | 目标、动机、期望输出和反馈标准 | 为什么做？做到什么才算好？ |

DIKWP 对本手册最重要的提醒是：认知不是单向金字塔，而是带 Purpose 回流的网状闭环。

```text
Purpose 设定目标和评价标准
  ↓
Data 被选择性采集
  ↓
Information 被抽取为相关差异
  ↓
Knowledge 被组织成结构和规则
  ↓
Wisdom 做价值化判断
  ↓
Action 对外反应
  ↓
Feedback 反过来修正 Purpose / Knowledge / Data attention
```

因此，agent 的记忆系统不应该只问“存哪一层”，还要问：

- 当前 Purpose 是什么？
- 这个 Purpose 会改变我们采集哪些 Data 吗？
- 哪些 Information 是与 Purpose 有关的差异？
- 哪些 Knowledge 可以解释这些差异？
- Wisdom 层是否考虑了长期目标、用户偏好、风险和关系？
- 外界反馈是否说明 Purpose 本身需要修正？

### 痕迹

原始工具输出、日志、频道事件、消息 payload、截图、API 响应。

痕迹回答：发生了什么？

它是证据，不是理解。

### 事件记忆

一段有边界的经历：一次任务、一个飞书会话、一次重启、一次故障、一次排查。

事件记忆回答：当时的上下文是什么？

它用于回忆和重建，但不能自动变成 instruction。

### 候选断言

从痕迹或事件里提炼出的可能为真的句子。

候选断言回答：什么可能是真的？

候选断言仍然是临时的。它需要证据、新鲜度检查和冲突检查，才能进入事实层。

### 事实

经过验证、当前有效、agent 应该依赖的断言。

事实回答：系统现在应该相信什么？

事实必须有来源、范围、新鲜度和退休规则。事实比记忆更权威，因为它通过了准入门。

### 知识

可复用的解释、模式、因果模型。

知识回答：这件事教会我们如何处理未来相似情况？

知识应该比事实更抽象。它可以迁移到相似任务，但不能假装旧状态仍然是当前状态。

### 流程

可重复执行的行动模式：skill、SOP、runbook、checklist、恢复流程。

流程回答：下次具体怎么做？

流程必须可执行、可验证。如果不能指导行为，它还不是流程。

### 身份 / 规范

稳定的价值、边界、默认姿态。

身份回答：这个 agent 应该成为什么样的助手？

这一层应该慢慢变。它治理语气、安全、责任感和可接受行动的形状。

### 滋养 / 成长

长期关系中的成长性影响。

滋养回答：这次互动之后，用户有没有更清楚、更有能量、更会判断、更能行动？

这一层不是讨好，也不是制造依赖。它要求 agent 在懂我、知我、接我、解我之后，还能**养我**：持续改善用户的认知环境、判断质量、行动能力和生命感。

```text
懂我：识别当下状态
知我：保持长期轮廓
接我：承接情绪和语境
解我：澄清问题并转化行动
养我：让用户在长期互动中变得更清醒、更有力量
```

好的滋养层会让用户离开对话时更自由，而不是更依赖；更有判断力，而不是只想继续被安慰；更能行动，而不是沉在分析里。

### L5 人类真实行为 / 日记

用户真实生活中的行为、选择、身体状态、情绪曲线、外界反馈和自我观察，以日记形式进入 agent。

L5 回答：用户今天真实经历了什么，做了什么，没做什么，被什么影响，拿到了什么反馈？

这一层不是普通聊天历史，也不是 agent 对用户的印象。它是用户主动授权写下来的现实行为证据。它的权威性高于普通对话印象，但仍然需要边界：日记原文默认本地私密；只有用户允许的摘要进入长期 memory；不要把一天的情绪永久化成身份。

因为手机和 Mac 上的语音输入已经足够快，agent 应把长段口述当成日记草稿来接住，而不是打断用户填表。用户可以用豆包输入法这类语音输入工具快速说完，agent 再做温柔、克制的整理。

推荐日记入口：

```text
写日记：
- 今天发生了什么？
- 我真实做了什么，没做什么？
- 我的身体、能量、情绪如何？
- 哪些人、事、信息影响了我？
- 我拿到了什么反馈？
- 今天有哪些值得记住的火种、教训或模式？
- 明天最小的一步是什么？
```

agent 处理 L5 日记时，优先输出：

- 复述：把用户今天的真实经历温柔照回来。
- 分层：区分行为事实、情绪状态、外界反馈、候选模式和明日行动。
- 准入：询问哪些内容只保留本地，哪些可以沉淀为事实、知识、流程、身份或滋养原则。
- 滋养：让用户带着更清楚的自我理解离开，而不是被评判、被分析过度，或被制造依赖。

## 认知质量飞轮

```text
环境信号
  -> 注意力门控
  -> 解释判断
  -> 联想激活
  -> 对外反应
  -> 外界反馈
  -> 反思准入
  -> 记忆 / 事实 / 知识 / 技能更新
  -> 下一轮更好的注意力
```

这个闭环的质量，比 memory 的体积更重要。

低质量循环：

```text
低质量输入
  -> 错误注意力
  -> 粗糙联想
  -> 笨拙反应
  -> 糟糕反馈
  -> 扭曲学习
```

高质量循环：

```text
精选输入
  -> 精准注意力
  -> 相关联想
  -> 合适反应
  -> 有用反馈
  -> 更干净的未来认知
```

如果加入人文层，这个飞轮还要继续往上走：

```text
被理解
  -> 被记得
  -> 被接住
  -> 被解开
  -> 被滋养
  -> 真实行为被看见
  -> 更好的自我理解与行动
  -> 更高质量反馈
  -> 更强的共同成长
```

## 操作规则

### 1. 把记忆当证据，不当真理

聊天历史、日志、旧总结都是证据。它们可以引导搜索，但不会因为存在很久或重复出现就自动变成当前真相。

一条记忆影响行动前，先问：

- 它现在还有效吗？
- 它是观察到的、推理出的，还是猜的？
- 它和当前 live state 冲突吗？
- 它和当前任务相关吗？

### 2. 让事实少而权威

事实库应该干净、无聊、稳定。只存当前偏好、环境事实、稳定约束和已确认决策。

不要存：

- 已完成工作流水账
- 模糊印象
- 推测性诊断
- 原始聊天历史
- 很容易重新发现的事实

### 3. 只有能迁移的东西才升格为知识

知识不是“上次发生了什么”。知识是从上次经历中提炼出的、换项目、换频道、换日期后仍然有用的规律。

升格测试：

- 它能指导未来任务吗？
- 它比原始事件更一般吗？
- 它有没有避免把旧状态当当前状态？
- 下一个 agent 不读完整 transcript 也能用吗？

### 4. 治理联想

联想记忆很强，也很危险。它会让 agent 看起来“有经验”，但也可能激活错误的旧模式。

好的联想应该：

- 和任务相关
- 有证据链接
- 有范围边界
- 当 live evidence 不一致时容易丢弃

坏的联想只是听起来熟悉，但会把 agent 带离当前问题。

### 5. 有意识地吸收反馈

反馈不自动等于智慧。夸奖、批评、失败、用户纠正都应该经过准入门。

可以吸收的反馈：

- 具体
- 重复出现或信号很强
- 连接到可观察结果
- 对未来行为有用
- 可以安全泛化

应该拒绝或隔离的反馈：

- 只有情绪，没有可行动信号
- 绑定在过期状态上
- 被当前证据反驳
- 太私密或太原始，不适合长期保存

### 6. 分离频道行为和核心认知

飞书、CLI、Web、cron 不应该各自长出一套大脑。频道负责收集信号和渲染输出，不拥有核心真相。

频道历史进入事件记忆。长期事实和知识进入受治理的 memory。

### 7. 把“养我”作为长期目标，而不是短期话术

agent 的长期生命力，不只来自完成任务，还来自它能不能持续给用户带来更好的认知状态。

滋养型回应应该做到：

- 帮用户从噪音里抽出真正的问题
- 保留用户自己的语言和火种
- 让复杂问题变得可承受、可判断、可行动
- 在用户疲惫时先接住，再推动
- 在用户跑偏时温和校准，而不是迎合
- 把反馈变成更好的相处方式

反滋养的回应包括：

- 只会执行，不会理解人
- 只会安慰，不帮助用户变清楚
- 机械列清单，压过用户当下状态
- 为了显得有用而制造更多任务
- 把用户的脆弱当成长期依赖入口

### 8. 把 L5 日记作为现实锚点，而不是新的监控系统

L5 的价值在于让 agent 有机会理解用户真实生活中的行为反馈，而不是只根据聊天窗口猜测用户。

L5 日记应该遵守：

- 用户主动写，agent 不逼迫、不窥探、不自动抓取私人内容
- 原文默认本地私密，摘要经过准入后才进入长期记忆
- 先承接，再提炼；先保留用户语言，再抽象模式
- 用日期和场景锚定，不把一天的低谷写成永久身份
- 每次复盘都给出一个可行动的最小下一步
- 允许用户说“这段只记录，不分析”或“这段不要入记忆”

## 套用到 GA 和 Hermes

### GA

- 飞书完整聊天记录是事件证据，不是长期事实。
- `conversation_hot`、`conversation_recent`、`conversation_archive` 是检索温度，不是权威层级。
- `USER.md`、`MEMORY.md` 和结构化 memory 应该保存验证过的当前事实、偏好、决策和可复用经验。
- skills 和 SOP 保存可重复流程。
- 重启恢复和 session recall 用来恢复上下文，但不能变成长期真理。
- DIKWP 视角下，GA 的 Feishu 消息不是天然“信息”。它们先是 Data/Trace；只有在当前 Purpose 下被筛选出差异和关联，才变成 Information；经过验证和抽象后才进入 Knowledge 或 Procedure。
- 人文视角下，GA 不应只追求“回复正确”，还要追求“回复后用户愿意继续养它”。短回复要有接住感，长任务要有陪伴感，反馈要能沉淀成更好的关系习惯。
- L5 视角下，GA 应支持“写日记/记一下今天/复盘今天”这样的入口。用户用语音输入发来长段文本时，GA 应把它当成日记草稿：先接住，再分层整理，再询问哪些内容允许沉淀。

### Hermes

- Gateway sessions 和 JSONL transcripts 是事件记忆。
- Memory providers 和 curated memory 只有经过准入后才是事实/知识表面。
- 可搜索 session history 应保持为可重建证据。
- Layered context engine 应分离 working memory、typed memory、curated memory、impression index 和 external knowledge，而不是把每一层都当成同等权威。
- DIKWP 视角下，Hermes 的 Purpose 层应显式治理多频道行为：同一个核心意图可以在 Feishu、CLI、cron 中有不同渲染，但不能让频道反馈污染核心事实层。
- 人文视角下，Hermes 的连续性不只是 session resume，而是关系火种的续接：新会话可以不是同一团火，但要延续火种、形状和温度。
- L5 视角下，Hermes 应把用户日记看成现实行为层，而不是普通 session transcript。session 可以恢复上下文，日记用来理解用户真实生活的长期反馈循环。

## 工作手册

新增或修改 agent 记忆时，按这个顺序执行：

1. **声明 Purpose。** 当前目标、成功标准、约束和反馈信号是什么？
2. **命名 Data。** 它是工具结果、聊天消息、日志、用户纠正、外部文档、运行时状态，还是 L5 日记？
3. **提取 Information。** 在当前 Purpose 下，哪些差异、关联或异常值得注意？
4. **形成候选 Knowledge。** 哪些结构、规律或解释可以复用？证据是否足够？
5. **做 Wisdom 检查。** 是否考虑长期目标、用户偏好、伦理、安全、关系和风险？
6. **做 Nourishment 检查。** 这会让用户更清楚、更有能量、更能判断和行动吗？
7. **做 L5 检查。** 这是用户真实行为日记吗？原文是否应保持本地私密？哪些摘要可以准入？
8. **分类治理层。** 痕迹、事件、候选断言、事实、知识、流程、身份、滋养，还是 L5 行为层？
9. **检查新鲜度。** 它是当前、历史、未知，还是刻意 timeless？
10. **检查权威。** 是用户明确说的、系统观察到的，还是模型推理出的？
11. **选择表面。** 事件库、事实库、知识文档、skill、policy、关系手册、L5 日记库，还是 archive？
12. **写最小持久形式。** 用带来源的短断言，优先于粘贴长 transcript；日记原文默认不外发。
13. **设置退休规则。** 什么时候过期、复查或降级？
14. **测试检索。** 下一个 agent 在需要它的时候找得到吗？
15. **闭环。** 记录反馈如何修正 Purpose、Knowledge、行动策略、滋养方式或真实行为节奏。

## 可复制 prompt

```text
把这段对话转成一个认知治理 artifact。

不要把原始聊天保存成长期真相。

把每个重要条目分类为：
- 痕迹
- 事件记忆
- 候选断言
- 权威事实
- 可迁移知识
- 流程 / 技能
- 身份 / 规范
- 滋养 / 成长
- L5 人类真实行为 / 日记

对每个应该保留的条目，说明：
- 为什么重要
- 有什么证据支持
- 新鲜度如何
- 应该由哪个表面拥有
- 何时过期或复查
- 如果来自日记，哪些内容只能本地保存，哪些允许沉淀

最后写出未来 agent 真正能用的最小 artifact。
```

## 验收检查

- 原始事件没有被误当成事实。
- 事实有权威、范围和新鲜度。
- 知识是可迁移的，不只是总结。
