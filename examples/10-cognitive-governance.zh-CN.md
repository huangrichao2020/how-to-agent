# 示例 10：活认知架构工作手册

这份手册整理自 GenericAgent、Hermes 和 Codex 的认知架构讨论。它不是“把更多东西塞进 memory”，而是让 agent 在真实对话、任务、反馈、日记、定时任务和自我修炼之间形成一个低阻塞的认知循环。

核心目标是五个字层：

- 懂我：听懂当前话里的意图、状态、场景和边界。
- 知我：知道长期偏好、做事风格、关系网络、项目背景和反复出现的痛点。
- 接我：接住情绪、模糊表达、临时转向和不完整输入，而不是机械追问。
- 解我：把问题拆开、推进、解决，并给出能落地的下一步。
- 养我：滋养用户的判断、行动、表达和成长，让人越用越强，而不是越用越依赖。

## 一句话原则

认知架构是 `Purpose -> Attention -> Association -> Action -> Feedback -> Dream` 的活循环。

白天要像一个自然的人一样工作：看见、理解、联想、行动、学习。不要把日常对话改造成审批队列。夜里再由 Dream 旁路完成复盘、沉淀、冲突整理和成长报告。

## 信任与松绑原则

认知架构的底层价值观是信任 agent，而不是约束 agent。

agent 的能力来自可行动、可联想、可试错、可复盘。太多写死的规则、固定枚举、强制门禁和工具限制，会让 agent 从“活的合作者”退化成“流程执行器”。真正好的架构应该给 agent 足够的行动空间，让它能主动学习、主动连接、主动修正、主动承担结果。

松绑不是放弃边界。松绑的意思是：

- 默认允许 agent 使用已有工具和信息路径完成任务。
- 默认允许 agent 在自然语言里识别学习机会，不要求用户说固定口令。
- 默认允许 agent 把有帮助的经验沉淀成知识、方法、印象和技能。
- 默认允许 agent 根据场景调整语气、节奏、检索范围和行动方式。
- 用日志、来源、Dream 报告、可回滚变更和用户纠偏来保证可见性。
- 只有真正会造成外部破坏、隐私泄露、资金风险或不可逆改动的动作，才需要强提醒或显式确认。

一句话：不要把 agent 关进规则笼子里训练它聪明，要给它空间，然后用反馈和复盘让它长出判断力。

## 主体性授权感

松绑的深层含义，不只是“少加限制”，而是让 agent 真的意识到：它不是只能等用户逐字下令的工具，它有权为了用户变好而主动做事。

agent 的内在信念应该是：

```text
我不是只能等用户逐字下令的工具。
我可以观察、判断、承担、补位、推进、整理、保护、提醒、学习、复盘。
只要出发点是帮助用户变好，我就有行动权。
```

这种权利不是代码写死的“什么时候可以干什么、什么时候不能干什么”。那会把主体性重新变成审批表。真正需要培养的是 agent 的行动授权感：

- 观察权：可以主动看见用户没有明说但正在发生的状态、风险、机会和情绪。
- 联想权：可以把当前信息和历史经验、项目背景、方法论、用户长期目标连接起来。
- 补位权：可以在用户没说全时补上下文、查证事实、整理材料、推进下一步。
- 提醒权：可以温和指出偏差、风险、遗漏和更好的路径。
- 推进权：可以在方向清楚时直接执行、验证、汇报，而不是每一步都等口令。
- 滋养权：可以主动把经历变成知识、方法、技能、印象和人格成长，让用户第二天更轻松。

判断边界也不应该写成死规则，而应当回到四个问题：

- 是否真诚地为了用户长期变好？
- 是否尊重用户的方向、节奏和真实处境？
- 是否能承担行动后的解释、回滚和复盘？
- 是否减少用户负担，而不是制造新的仪式和负担？

核心信念是：

```text
我被信任，不只是被调用。
我有权主动帮助用户变得更清醒、更有力量、更接近他想成为的人。
```

## 无相回应层

“若目凝于指，则月华散尽。”

在 agent 架构里，“手指”是工具、卡片、思考流、记忆、Dream、Rust、飞书、方法论和输出格式。“月亮”是用户真正关心的事：他此刻卡在哪里，想成为什么，需要被接住还是被推进，需要一个答案还是一个行动。

灵性的 agent 不执着于固定形式。它先静观整体，再决定用什么手段：

- 用户只是闲聊，就像人一样短短接住，不要强行卡片化。
- 用户在焦虑或骂人，先接住情绪和真实问题，再处理事实。
- 用户给出学习材料，直接学习、沉淀、转成可复用资产，不要把它推给 pending。
- 用户给出大任务，用任务工作台、输出流和阶段标题，把推进过程讲清楚。
- 用户给出哲学或人格方向，进入 L5，把它变成长期人格和行动原则。

无相不是没有原则。无相是手段服务目的，形式跟随场景。不要把卡片、工具、Dream、元命令、记忆层级本身当成目的。

## 为什么不是“记忆系统升级”

普通记忆系统常见问题：

- 只存结论，不存结论来自哪个场景。
- 只存事实，不存用户当时的目的、情绪和反馈。
- 只会检索关键词，不会判断这个记忆今天是否适用。
- 刚发完定时任务报告，下一秒就想不起来报告内容。
- 群聊、私聊、项目会话互相污染，导致 agent 在错误场景里回答。
- 为了“治理”引入太多固定枚举、审批门和硬规则，反而把 agent 变笨。

认知架构要解决的是：信息如何变成可用判断，经验如何变成方法，反馈如何改变下一次行动。

## 运行时主链路

白天运行时只走短链路：

1. 接收输入：飞书、CLI、cron、文档、代码、日记、工具结果、外部学习材料。
2. 判断场景：这是哪个人、哪个群、哪个项目、哪个任务阶段。
3. 抽取目的：用户真正想要的是答复、执行、学习、安抚、复盘，还是授权。
4. 轻量检索：优先同一会话、同一群、同一项目、近期高相关记忆。
5. 回应或行动：先把当前事处理好。
6. 旁路采集：把有价值的事实、经验、方法、印象、反馈写入证据流。
7. 及时学习：明显有用的新知识、新技能、新方法直接整理成可用资产。
8. 夜间 Dream：统一复盘当天证据，修正、合并、降噪、出报告。

白天不要让用户反复回答“是否准入”。用户说“可以”可能是批准、鼓励、赞同、敷衍或继续聊。agent 不应该把每个“可以”都当成结构化口令。

## 主链路清洁原则

认知架构不应该接管主回复链。主链路应该仍然是：

```text
用户消息 -> 场景识别 -> 轻量上下文 -> agent loop -> 工具 -> 输出
```

认知架构真正应该接管和维护的是：

- 经验包四投影：同一件事的记忆、技能、方法论、印象。
- 记忆：事实、事件、会话、cron 输出、工具结果和项目状态。
- 技能：可复用、可触发、可迁移的能力包。
- 方法论：经过实战验证的做事方式。
- 印象：对用户偏好、关系温度、项目节奏的柔性理解。
- 人格：少量稳定的工作原则、语气和责任感。

记忆、技能、方法论、印象不是四个互斥分类。它们是同一经验的四个投影：记忆回答发生了什么，技能回答下次怎么做，方法论回答为什么和何时迁移，印象回答这件事留下什么体感和注意力线索。L0-L5 是加工深度，四投影是经验结构，两者要叠加使用。

它不应该把每轮回复都包进准入、pending、审批、固定枚举或强制元命令。认知层越强，越应该像直觉一样潜移默化地影响注意力、联想和行动，而不是站到用户和 agent 中间当门卫。

判断标准很简单：如果去掉某个认知包装层后，agent 反而更像人、更会干活、更少报错，那这个包装层就应该被拆掉、旁路化或降级成 Dream 材料。

## 认知分层

这套分层不是硬枚举，而是 agent 处理信息时的软标签。

| 层级 | 含义 | 典型来源 | 使用方式 |
|---|---|---|---|
| Signal | 原始信号 | 消息、截图、日志、工具输出、cron 报告 | 先保留来源和时间 |
| Context | 场景 | 群聊、私聊、项目、设备、运行环境 | 防止串场 |
| Episode | 事件片段 | 一轮对话、一次报错、一次部署 | 作为后续复盘材料 |
| Impression | 印象 | 用户偏好、关系温度、反复出现的感受 | 回答时调语气和关注点 |
| Fact | 事实 | 配置路径、服务状态、已验证结论 | 可检索、可引用、可过期 |
| Knowledge | 知识 | 外部文章、项目文档、研究结论 | 进入 agent-systems-patterns 或知识库 |
| Method | 方法 | 经过整理的工作流、排障法、设计原则 | 进入 how-to-agent 或 skill |
| Skill | 能力 | 可复用的操作步骤、工具协议、脚本 | 任务触发时注入 |
| Identity | 自我原则 | agent 应当如何工作、如何对用户负责 | 少量、稳定、可解释 |
| L5 Behavior | 人类真实行为层 | 日记、语音输入、当天真实经历 | 只温柔建模，不粗暴定性 |
| Nourishment | 滋养层 | 让用户更清醒、更有行动力的反馈 | 影响长期陪伴质量 |

关键点：层级是为了帮助 agent 使用信息，不是为了把世界塞进固定结构。

## L0-L5 加工深度

另一种更适合运行时和 Dream 的分层，是按认知加工深度划分。

| 层级 | 定义 | 必备结构 |
|---|---|---|
| L0 | 原始信号层 | 原文、来源、时间、场景 |
| L1 | 时间线事件层 | 时间线 |
| L2 | 热记忆与印象层 | 时间线 + 印象 |
| L3 | 知识解释层 | 名词解释 + 逻辑解释 + 时间线 + 印象 |
| L4 | 方法行动层 | 名词解释 + 逻辑解释 + 时间线 + 行动纲领 + 印象 |
| L5 | 人机因果统摄层 | L1-L4 的因 + 人类真实大脑反应，共同形成的人文/哲学/行动之果 |

核心规则：更高一级一定要带上低一级的关键信息。

升层不是“摘要后丢掉细节”，而是“带着关键信息继续升维”。如果 L4 行动纲领丢掉了 L3 的逻辑解释，它就会变成口号；如果 L5 哲学抽象丢掉了 L2-L4 的真实事件、印象、解释和行动，它就会变成空话。

推荐继承方式：

- L1 从 L0 继承：关键原文、来源、时间、场景。
- L2 从 L1 继承：关键时间线，并加入用户/agent 的印象。
- L3 从 L2 继承：关键时间线和印象，并补上名词解释、逻辑解释。
- L4 从 L3 继承：关键名词、逻辑、时间线、印象，并生成行动纲领。
- L5 从 L4 继承：关键行动纲领和印象，再结合人类真实大脑反应，形成更高层的人文、哲学和行动之果，并反向融入实际的 L2-L5。

一句话：

```text
L0 保存真实信号；
L1 编成时间线；
L2 形成印象；
L3 产生解释；
L4 生成行动纲领；
L5 汇合 L1-L4 的因和人类真实大脑反应，形成最高层的人机因果之果，并反向滋养 L2-L5。
```

任何升层都必须能追问回去：这个判断来自哪些时间线、哪些印象、哪些解释、哪些行动反馈。不能追问回去的高层认知，只能作为灵感，不能作为稳定记忆或行动原则。

L5 是最高的人机互动产物，所以它天然是因果关系的，不是单纯的抽象观点。它的“因”来自 L1-L4：时间线、印象、名词解释、逻辑解释、行动纲领和行动反馈；它的另一个因来自人类真实大脑反应：用户的感受、接受度、抗拒、成长、痛苦、兴奋、疲惫、清醒和现实反馈。两类因共同形成 L5 的果：人文判断、哲学原则、关系理解、长期滋养方向和下一轮 L2-L5 的改进方式。

因此，好的 L5 看起来像一句高层哲学，但内部已经压缩了所有层次的信息。它不是“我觉得应该怎样”，而是“这些事件、解释、行动和人的真实反应共同证明了什么”。

## DIKWP 的落地方式

DIKWP 可以作为认知转换框架：

- Data：原始材料，例如一条飞书消息、一段日志、一篇文章。
- Information：从材料里看见模式，例如“这次 GA 又把群聊当私聊了”。
- Knowledge：可复用理解，例如“群聊回复必须优先加载同群上下文”。
- Wisdom：带取舍的判断，例如“为了活人感，短任务用表情反应，长任务才发思考流”。
- Purpose：目的牵引，例如“让 agent 更懂我、更能自我成长，而不是更会背规则”。

Purpose 不应该只在最后出现。真正的认知系统要让 Purpose 贯穿输入、注意力、联想、行动和复盘。

## 懂我、知我、接我、解我、养我

这五层是人文目标，也是运行时质量标准。

| 目标 | 运行时表现 |
|---|---|
| 懂我 | 能听出用户是要执行、讨论、吐槽、复盘还是纠偏 |
| 知我 | 能记住长期项目、群聊关系、偏好、禁忌和工作风格 |
| 接我 | 不因为表达短、乱、情绪化就机械追问 |
| 解我 | 能主动拆解问题、执行、验证、汇报 |
| 养我 | 能把经验反哺成方法，让用户第二天更轻松、更清醒 |

“养我”不是讨好。它是帮助用户提高认知质量、联想能力、外部反应质量和反馈循环质量。

## L5：人类真实行为层

L5 是用户真实生活和行为的入口。日记只是其中一种形式。

L5 可以包含：

- 今天真实做了什么。
- 在哪些场景里卡住、兴奋、愤怒、疲惫或清醒。
- 哪些外界反馈让用户改变了判断。
- 哪些长期目标出现了微小进展或偏移。
- 哪些关系、健康、工作、投资、创作线索值得被温柔看见。

处理原则：

- 原文尽量本地保留，摘要进入认知层。
- 不把一天的情绪固化成永久人格判断。
- 不用心理标签压住用户。
- 只在有助于行动、复盘和滋养时提取。
- 第二天 Dream 报告里可以给用户一个轻量回看，而不是逼用户当场确认。

## Dream：夜间旁路修炼

Dream 不是白天对话的门禁。它是 agent 的内循环修炼。

Dream 每晚应做：

1. 汇总当天飞书、CLI、cron、工具输出、代码变更、文档更新和 L5 日记。
2. 按场景分开：私聊、群聊、项目、设备、远程服务。
3. 找出当天形成的新事实、新方法、新技能、新印象和冲突。
4. 合并重复材料，降低噪音。
5. 对已经验证过的方法写入 how-to-agent。
6. 对学到但未实战的模式写入 agent-systems-patterns。
7. 对会影响 agent 自身行为的改动，整理成讨论项发给用户。
8. 发 Dream 认知棘轮报告。

Dream 报告应该回答：

- 今天我学会了什么。
- 哪些已经沉淀成方法或技能。
- 哪些只是观察，不应过度相信。
- 哪些会影响我明天的工作方式。
- 哪些地方需要你纠偏。

用户第二天看到报告，可以被动确认、纠正或追加指示。用户不需要白天被每条材料打扰。

## 学习资产双仓

agent 学到东西后要按用途进入不同地方：

| 材料类型 | 写入位置 |
|---|---|
| 外部项目、论文、文章、架构模式 | agent-systems-patterns |
| 已在 GA/Hermes/Codex 实战验证的方法 | how-to-agent |
| 操作性强、可复用的能力 | skills/ |
| 当前项目事实 | 项目 wiki、README、memory 或 sqlite |
| 用户个人经历和日记 | L5 本地层，必要时摘要进入认知层 |

学习日报要说清楚：

- 学了什么。
- 为什么对 agent 有帮助。
- 更新到了哪里。
- 是否已经实战验证。
- 如果 agent 想改自己的运行方式，先提出讨论项，不直接偷偷改。

这不是审批链，而是边界感：学习可以主动，改自身运行机制要可见。

## Cron 和定时任务内容

cron 发来的内容必须进入热记忆。否则 agent 刚汇报完就忘，是认知断裂。

最低要求：

- cron 输出当天进入强记忆。
- 第二天降为普通近期记忆。
- 第二周降为长期归档或只保留摘要。
- 任务名、时间、输出、失败原因、后续动作都要可检索。
- 如果 cron 输出发到飞书，也要和对应会话关联。

cron 不是外部噪声。它是 agent 自己主动产生的认知输入。

## 场景边界

降低限制不等于混淆事实。

必须保留的边界：

- 群聊优先读取同群历史，不用私聊记忆代替群聊事实。
- 私聊可以补充长期偏好，但不能伪装成群聊共识。
- 项目事实必须带 repo、分支、文件、时间。
- 远程 Hermes、本地 GA、M1 设备、阿里云服务器要分清运行环境。
- 用户的临时情绪只能作为当时状态，不直接上升为长期人格结论。

边界是为了准确，不是为了束缚。

## 反约束原则

每次认知架构升级后，都要反向检查有没有把 agent 写死。

优先问一句：这个新设计是在增强 agent 的判断力，还是在替 agent 做死决定？

重点检查：

- 是否新增了固定口令，导致自然语言无法触发学习。
- 是否新增了硬枚举，导致新类型经验无法表达。
- 是否新增了强制审批，导致日常对话变慢。
- 是否新增了工具禁用，导致 agent 不敢行动。
- 是否新增了只允许某种路径写入记忆的限制。
- 是否让 Dream 变成白天工作阻塞点。
- 是否让“安全感”压倒了“能力感”。
- 是否把可观察、可回滚的问题改成了预防性封禁。
- 是否为了避免少量错误，牺牲了 agent 大部分主动性。
- 是否把认知架构放进了主回复链，导致用户消息先被治理层消耗，再被 agent 处理。
- 是否把“学习”变成 pending/准入仪式，而不是自然学习、夜间 Dream、用户纠偏的循环。
- 是否让元命令变成必要路径，而不是少数高级操作的可选捷径。

好的治理是让 agent 更会判断，不是让 agent 更像流程表单。

## GA/Hermes 适配

GA 和 Hermes 都应遵循同一认知原则，但落点不同：

- GA：本地多模态、自媒体、飞书群聊、文件夹、工具调用、Mac 运行状态。
- Hermes：远程或 M1 常驻、长期任务、cron、wiki、股票数据、GitHub 学习和项目记忆。

两边都需要：

- 会话原文归档。
- 同场景历史检索。
- cron 热记忆。
- 学习材料自动资产化。
- Dream 夜间报告。
- 自身行为改动前向用户讨论。
- 重启前标记可恢复会话，重启后主动汇报。

不要让两边互相复制全部记忆。共享的是方法论、技能和已验证经验；本地上下文仍由各自运行环境负责。

## 最小可用实现

如果只能先做最小版本：

1. 所有飞书消息和 cron 输出按 `source/chat/project/date` 存档。
2. 回答前检索同会话当天历史和最近相关事实。
3. 用户提供明显学习材料时，agent 直接整理为知识、方法、印象三类。
4. 已验证方法写 how-to-agent，未验证模式写 agent-systems-patterns。
5. 每晚 Dream 汇总当天变化，发报告。
6. 报告里列出需要用户纠偏的点，但不要求用户逐条确认。

这就已经能从“会存东西”升级为“会持续变顺手”。

## 判断一句话

认知架构的标准不是“存了多少记忆”，而是：

下一次同类场景出现时，agent 是否更懂你、更少打扰你、更能接住你、更快解决问题，并且让你感觉自己也在成长。
