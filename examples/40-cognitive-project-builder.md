# Example 40: From User Experience To Cognitive Project

This method turns a user's domain experience into a durable cognition project.
It came from building an emotional-coach project, but the pattern is general.

## Core Rule

The user must supply the domain keywords, key concepts, lived lessons, opinions,
and real scenarios. The agent should not invent a field from generic knowledge.
The agent's job is to structure the user's experience density.

```text
Cognitive projects are not AI knowledge summaries.
They are the user's experience made systematic.
```

## Evolution Chain

```text
raw lived material -> high-energy maxims -> models -> coaching workflow
-> anonymized cases -> reusable skill project
```

More explicitly:

```text
user supplies domain seeds
-> agent extracts keywords and concepts
-> user and agent confirm maxims
-> agent builds models and layers
-> user supplies more real cases
-> agent abstracts cases
-> agent creates coaching workflow
-> agent packages the project
-> new scenarios keep refining modules and cases
```

## User Seed Layer

Ask for:

- domain name
- core keywords
- key concepts
- lived lessons
- real scenarios
- common misjudgments
- target problems
- executable maxims

## Agent Output Layer

Produce:

- terminology
- state machines
- stage models
- decision tables
- operating handbooks
- coaching output templates
- anonymized cases
- skill project structure

## Package Shape

```text
project/
├── README.md
├── SKILL.md
├── SKILL.zh-CN.md
├── methodology/
│   └── index.zh-CN.md
├── references/
│   └── module-name.zh-CN.md
└── cases/
    └── case-01-topic.zh-CN.md
```

## One-Line Summary

Do not start from theory. Start from lived pain. Compress insight into maxims,
turn maxims into models, models into coaching, coaching into cases, and cases
into a reusable skill.
