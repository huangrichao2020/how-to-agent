# 原子级拆解法：通用工作流优化方法论

## Purpose

从网红合作AI助手案例提炼的四步框架：场景锚定→原子级拆解→AI增强矩阵(L1-L4)→落地路径。适用于任意SOP/工作流/技能/经验包的AI增强升级。核心心法：不整体替换，要节点增强；拆解越细增强越准；先辅后全保留回滚。

## Proven By

基于飞书文档 MTOBwoUCbiTcPbkLjZFc710mnxf 中的'网红达人合作AI助手——原子级拆解案例'提炼，已验证可迁移到SOP优化、工作流自动化、技能沉淀、经验包产品化等场景。

## Reusable Procedure

1. 先锚定终局场景：写清参与者、平台、必须发生的动作、禁止事项和验收证据。不要从第一个表面 bug 开始修。
2. 调查真实拓扑：repo、运行进程、日志、权限、平台行为、状态存储、队列、双端部署和已有经验系统。
3. 拆到原子动作：每个动作只保留一个触发、一个角色、一个输入、一个判断、一个输出、一个失败模式。
4. 做四象限和 A/B/C 分级：高频高耗时优先；A 类自动化，B 类 agent 主导加兜底，C 类认知辅助。
5. 选择 L1-L4 增强层级：建议、半自动、全自动、自进化逐步升级，必须保留回滚和数据闭环。
6. 设计主链路/旁路/worker：主链路处理当前可见任务；补漏、截断续片、历史恢复尽量旁路；额外分片交给 worker/队列。
7. 落地最小垂直切片：优先复用已有 rails、skill registry、state store、experience system，不为一个症状新增一整层复杂度。
8. 做场景级验证：如果问题发生在飞书群聊、文档权限、双 agent 接力或运行时恢复，就要验证这些真实表面，而不只跑单测。
9. 沉淀和同步：把新规则写进 skill/reference/memory/SOP；GA/Hermes 这类镜像 agent 要两边同步并记录差异。

## When To Use

Use when a future agent faces workflow/SOP/toolchain/multi-agent optimization work, especially when a user is really asking for an end-to-end operating scene instead of a local patch.

## Guardrails

Treat this as a living method: use judgment, adapt to the current repo/runtime, and update after real feedback.
