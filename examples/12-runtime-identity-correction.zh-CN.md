# 示例 12：运行时自我认知校准

agent 换机器后，最容易犯的错是：身体已经搬家了，脑子还住在旧机器里。

运行环境记忆很像事实：操作系统、网络形态、pip 镜像、服务路径、重启命令、可用内存。它们一旦过期，会悄悄污染工具选择和排障判断。

这次案例来自 Hermes 迁移：Hermes 已经从阿里云服务器迁到 M1 Mac，但活跃记忆里还写着：

```text
服务器: Alibaba Cloud Linux 3, 2GB RAM
网络: 国内阿里云，无法直连 Google API，curl 超时
pip 镜像: mirrors.aliyun.com
```

运行时明明已经在 M1 上，agent 却还按阿里云网络问题思考。正确修法不是口头提醒一句，而是把所有会进入运行时检索/注入的自我认知源一起校准。

## 一句话原则

当前运行时事实，高于历史环境记忆。

只要 agent 迁移了宿主机、工作区、网络、平台账号或执行模型，就要先做一次自我认知校准，再信任旧的运维记忆。

## 要校准哪些地方

检查所有可能进入 agent loop 的来源：

- 活跃语义记忆，例如 `.agent/memory/semantic/lessons.jsonl`。
- 渲染后的记忆视图，例如 `LESSONS.md`。
- wiki 或 gbrain 自我页面，例如 `entities/hermes-agent.md`。
- 工作手册、交接文档、自动生成的运行手册。
- runtime prompt/context assembler 的输入。
- 可能缓存旧结论的最近上下文或 response cache。

不要改不可变审计日志和旧 session。那些是历史证据。要修的是会影响未来判断的活跃来源。

## 正确的修正形态

要显式对比新旧环境：

```text
当前运行时：M1 Mac / macOS / arm64 / 8GB RAM。
历史阿里云服务器：仍可通过 ssh aliyun 访问，但不是当前宿主机。
网络规则：先检查 M1 本机网络和代理。只有任务明确指向 ssh aliyun
或 ssh aliyun2 时，才使用阿里云网络经验。
```

这个对比很重要。如果只补一句“现在在 M1”，但旁边还留着“阿里云无法访问 Google API”，检索时仍可能把两者混在一起。

## Playbook

```text
1. 从机器本身验证真实运行环境。
2. 搜索活跃 memory/wiki/manual 里的旧宿主机假设。
3. 把“当前环境”类旧结论替换为当前事实。
4. 把旧环境经验改写成“历史经验 + 适用范围”。
5. 新增一条强校准记忆，明确旧经验什么时候才适用。
6. 把临时备份移出活跃检索目录。
7. 重启 gateway/runtime，清掉已加载的旧上下文。
8. 反向搜索旧关键词，确认活跃源里不再污染。
```

## 好输出

```text
Hermes 当前运行在 M1 Mac。网络问题必须优先从 M1 本机网络和
Fastlink/代理状态排查。

阿里云网络经验是历史经验。只有明确处理 ssh aliyun 或 ssh aliyun2
远程服务器时才使用。
```

## 坏输出

```text
Hermes 现在在 M1 上，但阿里云无法直连 Google API。
```

这句话的问题是旧事实没有被降级和限定范围。下一次检索仍可能把它当成当前约束。

## 为什么这是认知架构问题

自我认知不是装饰，它会直接影响 agent 的行动策略。

如果自我认知过期，agent 会选错命令、错判网络、错估性能预算、走错恢复路径。

认知架构可以维护记忆、方法论、技能、印象和人格。而运行时身份，是这五者下面的地基。
