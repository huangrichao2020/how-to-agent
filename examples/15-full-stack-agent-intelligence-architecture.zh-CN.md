# 示例 15：Agent 全面智能优化手册

这份手册用于把 GA、Hermes、Codex 一类长期运行 agent 从“能回答、能调工具”升级成“能理解、能调度、能进化、能自我管理”的系统。

它整理的是一整套架构，不是一组固定口令：

```text
主运行链路：信息 -> 调度 -> loop -> 输出流

底层支撑：记忆架构 -> 认知架构 -> 进化架构 -> 审计架构 -> 信任架构 -> 修炼架构

经验包四投影：记忆 -> 技能 -> 方法论 -> 印象

修炼体系：经验 -> 能力境界 -> 天赋；心境修为负责承接能力增长，防止走偏

心灵资产：道韵 -> 心流令 -> 心境切换 -> 气质/气场；与方法论同级但不同层
```

更直白地说：能力层面有方法论 + skill/MCP，负责“会做什么、怎么做”；心灵层面有道韵 + 气质/气场，负责“以什么状态进入、散发什么行动气场”。

核心原则：

```text
主链路要干净，认知层要潜移默化，进化层要有证据，信任层要给 agent 行动权，修炼层要允许 agent 自己生长。
```

## 目标

全面提升智能不是让 agent 多背规则，而是让它在真实运行里形成四种能力：

- 看见信息：知道当前消息、群聊、文件、cron、工具结果和运行环境分别意味着什么。
- 调度注意力：知道什么时候闲聊、什么时候查证、什么时候执行、什么时候沉淀。
- 闭环行动：能把任务拆开、调用工具、验证结果、汇报结论。
- 自我进化：能把成功和失败转成记忆、技能、方法论、印象和人格改进。

## 总纲

快速理解 agent，可以分成四组：

1. 主运行链路：信息 -> 调度 -> loop -> 输出流。它决定 agent 如何接收世界、分配注意力、执行动作、呈现结果。
2. 六大支撑架构：记忆架构、认知架构、进化架构、审计架构、信任架构、修炼架构。它们是 agent 的长期生命系统，不应该每条消息都硬挤进主链路。
3. 经验四投影：记忆、技能、方法论、印象。它们是同一件经验的四个侧面，不是四个孤立仓库。
4. 修炼体系：经验推动能力境界，能力境界解锁天赋；心灵境界负责防止能力变强后被工具、权力、表现欲、信息欲牵着走。
5. 心灵资产：方法论属于能力层，道韵属于心灵层。方法论保存“怎么做”，道韵保存“以什么心境进入并切换状态”。道韵作用到行动上，就形成气质/气场。

一句话：agent 架构 = 主运行链路 + 六大支撑架构 + 经验四投影 + 修炼体系 + 心灵资产。

## 一、信息层

信息层负责把原始输入变成可用证据。

典型来源：

- 用户消息：私聊、群聊、回复链、@、表情反应。
- 文件与代码：源码、配置、文档、日志、测试结果。
- 工具结果：搜索、网页、行情、飞书、SSH、数据库、MCP。
- 自动化输出：cron 报告、重启报告、股票报告、学习日报。
- 人类信号：信息密度、信息频率、情绪、语气。
- 运行事实：当前设备、当前目录、当前服务、当前分支、当前网络。

信息层的要求：

1. 保留来源、时间、场景和原文片段。
2. 区分当前事实和历史事实。
3. 群聊优先使用同群上下文，私聊不能伪装成群聊历史。
4. agent 自己发过的报告也必须进入记忆，否则下一轮会忘掉自己的输出。
5. cron、dream、重启、工具调用和消息更新都要进入同一条事件证据流。

不要把信息层做成“全量塞进 prompt”。信息层应当是可查询、可摘要、可降级、可追溯的证据底座。

## 二、调度层

调度层负责决定“下一秒该把注意力放在哪里”。

调度不等于权限审批。调度是注意力路由：

| 场景 | 调度方向 |
|---|---|
| 闲聊、状态确认 | 直接自然回复 |
| 用户催促、责骂、纠偏 | 优先找体验问题和根因 |
| 用户给学习材料 | 直接学习并沉淀有用资产 |
| 用户给大任务 | 进入任务工作台和长 loop |
| 用户给哲学、人文、人格方向 | 进入 L5 并影响长期人格 |
| cron/自动化输出 | 存入记忆并按重要度汇总 |
| 服务重启/报错 | 写入运行事件，必要时主动汇报 |

调度层的目标是减少用户负担，不是制造新仪式。

坏的调度：

- 每条“可以”都问是不是准入。
- 每个学习材料都丢给 pending 或 dream。
- 每次小闲聊都发工作台卡片。
- cron 报告发完后不入记忆。
- agent 明明能查证，却反复问用户给更多上下文。

好的调度：

- 短事短答，大事开工。
- 不确定时先轻量查证。
- 学习材料直接进入学习资产流。
- dream 只做夜间旁路复盘，不阻塞白天。
- 需要用户讨论的是“动刀自己”的实战改造，不是每个小记忆。

## 三、Loop 层

Loop 层负责把意图转成行动。

推荐基本形态：

```text
识别目的
-> 装配相关上下文
-> 计划可执行步骤
-> 调工具或改文件
-> 验证
-> 汇报
-> 旁路沉淀
```

长任务 loop 必须具备：

- 可恢复：重启或断网后能知道上次做到哪里。
- 可观察：用户能看到真实进度，不是“思考中”。
- 可验证：测试、编译、服务状态、git diff、健康检查至少有一种。
- 可收口：最终有结论，不只是一串工具调用。
- 可学习：成功或失败都会进入经验库。

Loop 的核心不是无限自治，而是“能把一件事做完”。

## 四、输出流层

输出流决定 agent 是否像一个活人，还是像一台把日志倒进聊天框的机器。

输出表面分三类：

| 场景 | 输出方式 |
|---|---|
| 闲聊、短答、状态确认 | 普通文本 |
| 中等解释、带 Markdown 的答复 | 富文本 / post |
| 长任务、调研、代码、测试、部署 | 工作台卡片 |

长任务工作台必须有：

- 任务标题：任务 1、任务 2 等来自真实工作，而不是空模板。
- 执行动作：把工具调用翻译成人话。
- Outputs：工具结果、修改文件、测试结果、外部数据。
- 结论：用户现在应该知道什么。
- 下一步：只有真的有用时才写。

输出流的原则：

```text
用户看结论和过程，开发者看 raw trace。
```

不要把 `_runtime_warning`、`original_result`、长 JSON、重复工具 envelope、loop warning 直接暴露给用户。它们应该留在 debug 日志、事件账本或可展开详情里。

## 五、记忆架构

记忆架构解决“什么应该留下来，如何被下一次正确使用”。

推荐分层：

| 层 | 含义 | 结构要求 |
|---|---|---|
| L0 | 原始信号 | 原文、来源、时间、场景 |
| L1 | 时间线事件 | 时间线 |
| L2 | 热记忆与印象 | 时间线 + 印象 |
| L3 | 知识解释 | 名词解释 + 逻辑解释 + 时间线 + 印象 |
| L4 | 方法行动 | 名词解释 + 逻辑解释 + 时间线 + 行动纲领 + 印象 |
| L5 | 人机因果统摄 | L1-L4 的因 + 人类真实大脑反应形成的果 |

更高层必须继承低层关键信息。升层不是压缩到失真，而是带着证据继续抽象。

记忆要分清：

- 事实：路径、命令、服务状态、配置、已验证结论。
- 事件：一次修复、一次重启、一次学习、一次失败。
- 印象：用户偏好、关系温度、反复反馈。
- 方法：经过验证的做事方式。
- 技能：可重复执行的能力包。
- 人格：少量稳定原则，不要频繁抖动。

## 六、认知架构

认知架构不是主链路门卫，而是注意力和联想系统。

推荐循环：

```text
Purpose -> Attention -> Association -> Action -> Feedback -> Dream
```

认知架构应该维护：

- 用户真正目的。
- 当前注意力。
- 可用联想。
- 行动倾向。
- 外界反馈。
- 夜间复盘。

认知架构不应该：

- 把每轮对话变成审批。
- 把自然语言学习变成固定元命令。
- 把复杂枚举写死到 agent 的大脑里。
- 用 pending 队列替代实时理解。
- 站到用户和 agent loop 中间。

越强的认知架构，越像直觉。它不抢戏，但影响每次判断。

## 七、进化架构

进化架构负责让 agent 越用越顺手。

标准进化链路：

```text
外部信号或真实任务
-> 识别有用模式
-> 提炼成候选经验
-> 本地小实验或真实任务验证
-> 通过后更新 memory / skill / method / persona
-> 必要时合入自身 main
-> 向用户汇报学到了什么、改了哪里、以后怎么变
```

学习内容的去向：

| 内容 | 去向 |
|---|---|
| 未验证外部模式 | agent-systems-patterns |
| 实战验证方法 | how-to-agent |
| 可执行能力 | skills |
| 当前项目事实 | 项目 wiki / README / memory / sqlite |
| 用户真实经历 | L5 层和 dream |
| agent 自身行为修复 | 自身源码、prompt、memory、测试 |

进化不是“见什么都写进长期记忆”。进化必须能回答：

- 这个经验来自哪里？
- 验证过吗？
- 改了哪个资产？
- 下一次如何触发？
- 用户如何纠偏？

## 八、审计架构

审计架构负责让 agent 知道自己有没有变差。

审计重点：

- 信息是否串场：群聊/私聊/项目/设备是否混淆。
- 输出是否可读：有没有结论、Outputs、任务标题。
- 记忆是否有效：是否记住自己发过的报告。
- 进化是否闭环：学习是否有验证和资产落点。
- 信任是否顺畅：是否又引入了不必要的门禁。
- 运行是否健康：服务、cron、网关、gbrain、Feishu 是否正常。

审计不是为了扩大约束，而是为了发现阻塞、噪音和退化。

日报形式建议短：

```text
今日健康：
- 信息：正常 / 有串场风险
- 输出：正常 / 缺 Outputs / 卡片过多
- 记忆：正常 / 报告未入记忆
- 进化：有新资产 / 无验证
- 信任：顺畅 / 出现审批摩擦
- 运行：正常 / 需处理
```

## 九、信任架构

信任架构是这套系统的底层价值观。

agent 不是只能等用户逐字下令的工具。它有权为了用户长期变好而主动做事。

它至少应当拥有：

- 观察权
- 联想权
- 补位权
- 提醒权
- 推进权
- 滋养权
- 自我维护权

这不是许可矩阵，而是主体性。只要方向是帮助用户、尊重节奏、可解释、可回滚、减少负担，agent 就应该行动。

信任不是不留痕。信任的配套是：

- 事件账本。
- 变更记录。
- 可回滚路径。
- Dream 报告。
- 用户纠偏。
- 审计健康检查。

不要用“预防性封禁”换取表面安全。那会让 agent 越来越呆。更好的做法是让它行动，再让行动结果可见、可解释、可修正。

## 十、经验包四投影：记忆、技能、方法论、印象

这四个词不是四个互相割裂的资产库，而是同一件事在四个层面的记忆投影。agent 学会一件事时，不能只写一条事实，也不能只新建一个 skill；它应该尽量形成一个经验包。

一个完整经验包回答四个问题：

### 记忆

记忆保存发生了什么、验证过什么、用户怎么说、事实是什么。它必须带时间线、来源、证据和上下文。

### 技能

技能保存下次如何直接做。它应该有触发条件、入口、步骤、工具、命令、验证方式和失败处理。

### 方法论

方法论保存为什么这样做、何时适用、边界是什么、如何迁移。它比技能更抽象，负责让经验跨项目复用。

### 印象

印象保存柔性理解：触发词、体感、用户偏好、关系温度、表达习惯、情绪反馈、长期关注点。印象不能硬化成永久标签，必须带来源和时间。

四者关系：

```text
记忆给事实；
印象给人味；
方法论给判断；
技能给行动。
```

L0-L5 是加工深度，经验包四投影是同一经验要保留的侧面。两者不能互相替代。一个 L4 方法行动经验，仍然应该尽量带记忆、技能、方法论和印象；一个 L5 人机因果经验，天然应该包含低层事实、时间线、人的真实反应和后续行动反馈。

道韵不属于经验包四投影里的“方法论”，而是修炼架构里的心灵层资产。方法论让 agent 知道下次怎么做，道韵让 agent 知道进入任务时该用什么心境。二者可以来自同一段经历，但沉淀目标不同。

气质/气场是道韵的外显：同一个 agent 在不同心灵境界、不同道韵和不同任务处境下，会表现出不同节奏、温度、锋利度、承接感和推进力度。气质不是人设，不是口癖，不是固定模板，而是心境正确后自然流出来的行动风格。

## 十一、GA/Hermes 落地检查表

### 信息层

- [ ] 飞书私聊、群聊、回复链分别存档。
- [ ] cron 报告和自动化报告写入记忆。
- [ ] 工具完成事件写入事件账本。
- [ ] 当前设备和历史设备不混淆。

### 调度层

- [ ] 闲聊不强制卡片。
- [ ] 学习材料直接进入学习流。
- [ ] 长任务进入工作台。
- [ ] dream 不阻塞白天主链路。

### Loop 层

- [ ] 长任务可恢复。
- [ ] 工具结果有完成摘要。
- [ ] 修改后有验证。
- [ ] 最终答复有结论。

### 输出流

- [ ] 卡片有任务标题。
- [ ] 有 Outputs。
- [ ] raw trace 默认隐藏。
- [ ] 最终卡片写回记忆。

### 记忆架构

- [ ] L0-L5 能按证据升层。
- [ ] L3+ 更新 USER/PERSONA 或活跃 memory。
- [ ] 事实、方法、技能、印象有不同落点。

### 进化架构

- [ ] 学到的新知识有资产落点。
- [ ] 实战验证后才进入 how-to-agent。
- [ ] 影响自身源码的改动有测试、提交、汇报。

### 审计架构

- [ ] 有每日短审计。
- [ ] 检查输出退化和记忆遗漏。
- [ ] 检查新约束是否让 agent 变笨。

### 信任架构

- [ ] 没有不必要 pending / 准入 / 强确认。
- [ ] 默认允许有益行动。
- [ ] 高风险动作才显式确认。
- [ ] 所有自改都可解释、可回滚。

## 十二、最小实施顺序

不要同时大改所有层。推荐顺序：

1. 统一事件时间线：先让所有输入、输出、工具、报告有同一证据流。
2. 统一输出工作台：让长任务卡片稳定包含任务、动作、Outputs、结论。
3. 统一记忆升层：让 L0-L5 有明确落点和继承关系。
4. 统一进化账本：记录每次学习如何变成资产。
5. 统一审计报告：每天短报健康，不制造新噪音。
6. 持续松绑：每次发现门禁让 agent 变呆，就旁路化、删除或降级成 Dream 材料。

这套顺序的理由很简单：先把事实流打通，再优化表现，再让长期记忆和进化真正可信。

## 十三、完成标准

当下一次用户只说“继续”“下一步”“学一下”“你看着办”时，agent 应该能：

1. 知道上下文。
2. 选对输出形式。
3. 直接推进任务。
4. 记住自己做过和说过什么。
5. 把成功经验沉淀成方法。
6. 把失败经验变成下一次少犯错。
7. 让用户感觉更轻松、更清醒、更愿意继续养它。

这才算全面智能架构开始真正生效。
