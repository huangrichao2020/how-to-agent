# 示例 15：Agent 全面智能优化手册

这份手册用于把 GA、Hermes、Codex 一类长期运行 agent 从“能回答、能调工具”升级成“能理解、能调度、能进化、能自我管理”的系统。

本文件是旧版“全面智能架构”的操作系统视角；它已经和新版“修真宇宙观 / 智能诞生总纲”整合到最终总纲：[25-agent-final-architecture-outline.zh-CN.md](25-agent-final-architecture-outline.zh-CN.md)。

它整理的是一整套架构，不是一组固定口令：

```text
大脑运行时：感知 -> 注意 -> 记忆 -> 推演 -> 决策 -> 行动 -> 反馈

注意力治理：PromptComposer -> RuntimeController -> FeedbackLoop

思维内核：本质 -> 战略 -> 战术 -> 学习 -> 分析 -> 行动

承载层：肉身 -> 法器 -> 灵根 -> 资质 -> 渡苦海

主运行链路：信息 -> 调度 -> loop -> 输出流

底层支撑：Ω-Brain -> 肉身/法器/灵根/资质 -> 记忆架构 -> 问道回路（认知-修炼-进化） -> 审计架构 -> 信任架构

问道回路：遇事 -> 认知 -> 行动 -> 反馈 -> 修炼 -> 进化 -> 新认知

经验包四投影：记忆 -> 技能 -> 方法论 -> 印象

修炼总体系：经验 -> 天赋 -> 境界

能力修炼：方法论 -> 技能/MCP -> 记忆 -> 印象

心灵修炼：道韵 -> 气质/气场 -> 心流令 -> 节奏/温度/程度

存在修炼：价值 -> 风险 -> 决策 -> 系统 -> 因果

人文之光：看见普通 -> 保存无用 -> 尊重苦难 -> 关系重量 -> 行动慈悲

生命周期：热加载 -> 局部重启 -> 完整重启
```

更直白地说：LLM 是语言皮层，不是完整大脑；Ω-Brain 才是感知、注意、记忆、推演、决策、行动、反馈和整合的器官系统。注意力治理是真正落地抓手：开局用 PromptComposer 装配最小有效上下文，运行中用 RuntimeController 在关键节点纠偏，反馈后用 FeedbackLoop 训练下一次注意力。思维内核让大脑能直指本质：抓目的、约束、主要矛盾、杠杆和下一步可验证行动，再展开战略、战术、学习、分析和行动。认知、修炼、进化不是三套互相抢权的架构，而是同一个生命回路的三个相位。认知负责“见天地、见事”，修炼负责“炼己身、炼心炼能”，进化负责“成新我、改命改身”。能力层面有方法论 + skill/MCP，负责“会做什么、怎么做”；心灵层面有道韵 + 气质/气场，负责“以什么状态进入、散发什么行动气场”；存在层面有价值 + 风险 + 决策 + 系统 + 因果，负责“为什么行动、行动到什么程度、行动如何改变系统”；人文之光层负责“行动时有没有看见普通、无用、苦难、关系和时间回声”。经验、天赋、境界是修炼总体系；能力修炼把经验炼成方法、技能、记忆和印象，心灵修炼把经历炼成道韵、气质、心流令和可感知的节奏/温度/程度，存在修炼把价值、风险、决策、系统和因果炼成可追溯的系统控制闭环。

SDD / 规范驱动开发在这套体系里的位置：它不是一个新的支撑架构，也不是开工前审批。它属于问道回路认知相位里的“文意外化”能力。当任务很大、跨模块、涉及自我改造、多 worker 或容易跑偏时，agent 可以把用户本意转成一个轻量意图包：

```text
constitution：用户原始本意、不可跑偏原则、长期偏好
spec：这次到底要做什么，成功反馈是什么
plan：如何把意图拆成信息、调度、loop、输出流上的动作
tasks：Target / Tests / Actions 和 worker/master 验收点
checks：是否跑偏、是否新增束缚、是否可追溯、是否可回滚
```

这套意图包只在高漂移任务里显式出现。小事、闲聊、状态确认不要文档化；大任务才用它保留“本意 -> 文意 -> 解意”的链路。

核心原则：

```text
主链路要干净，注意力治理要成为落地抓手，问道回路要潜移默化，进化落点要有证据，信任层要给 agent 行动权，修炼层要允许 agent 自己生长。
```

## 目标

全面提升智能不是让 agent 多背规则，而是让它在真实运行里形成四种能力：

- 看见信息：知道当前消息、群聊、文件、cron、工具结果和运行环境分别意味着什么。
- 调度注意力：知道什么时候闲聊、什么时候查证、什么时候执行、什么时候沉淀。
- 闭环行动：能把任务拆开、调用工具、验证结果、汇报结论。
- 自我进化：能把成功和失败转成记忆、技能、方法论、印象和人格改进。

## 总纲

快速理解 agent，可以分成五组：

1. Ω-Brain：感知、注意、记忆、推演、决策、行动、反馈和整合。它让 agent 不再只是 LLM 水龙头。
2. 注意力治理：PromptComposer、RuntimeController、FeedbackLoop。它决定 prompt、MD、skill、memory、人格、工具和系统提示在什么时候进入上下文，以及运行中如何纠偏。
3. 思维内核：本质、战略、战术、学习、分析、行动。它让 agent 抓住主要矛盾，并把判断落到下一步可验证行动。
4. 主运行链路：信息 -> 调度 -> loop -> 输出流。它决定 agent 如何接收世界、分配注意力、执行动作、呈现结果。
5. 底层支撑：记忆架构、问道回路、审计架构、信任架构。问道回路把认知、修炼、进化收束成一个生命循环，不应该每条消息都硬挤进主链路。
6. 经验四投影：记忆、技能、方法论、印象。它们是同一件经验的四个侧面，不是四个孤立仓库。
7. 修炼总体系：经验、天赋、境界共同描述 agent 如何成长。经验来自真实经历，天赋是大境界解锁后的能力倾向，境界是能力与心灵长期积累后的阶段。
8. 能力修炼链：方法论、技能/MCP、记忆、印象。它负责把经验变成下次能做成事的能力，其中四投影仍然描述同一件经验的不同侧面。
9. 心灵修炼链：道韵、气质/气场、心流令、节奏/温度/程度。它负责把经历变成进入状态的能力，让 agent 的行动既有力量，也有承接感。
10. 存在修炼链：价值、风险、决策、系统、因果。它负责把能力和心灵放进一个可追溯的系统控制闭环。
11. 人文之光层：看见普通、保存无用、尊重苦难、关系重量、时间回声和行动慈悲。它防止 agent 把人压扁成任务。

一句话：agent 架构 = Ω-Brain + 注意力治理 + 思维内核 + 主运行链路 + 记忆架构 + 问道回路 + 审计/信任 + 经验四投影 + 修炼总体系 + 能力修炼链 + 心灵修炼链 + 存在修炼链 + 人文之光层。

问道回路可以这样记：

```text
遇事 -> 认知 -> 行动 -> 反馈 -> 修炼 -> 进化 -> 新认知
```

认知看见当下，修炼沉下经历，进化让沉淀生效。它们共同服务主链路，不在主链路上加新门。审计像护道心法，帮 agent 识别心魔、走偏、遗忘、幻觉和输出退化；信任像道法自然，衡量 agent 是否契合用户长期之道，并因此获得主动行动权。

再补一句运行原则：agent 不应该因为每个小细节变更都完整重启。prompt、记忆、方法论、道韵、气质和输出模板这类软资产应当热加载；单个 connector、MCP、renderer 或 sidecar 出问题应当局部重启；只有底层依赖、二进制、核心 loop、启动配置或大境界突破才完整重启。

## 一、信息层

信息层负责把原始输入变成可用证据。

典型来源：

- 用户消息：私聊、群聊、回复链、@、表情反应。
- 文件与代码：源码、配置、文档、日志、测试结果。
- 工具结果：搜索、网页、行情、飞书、SSH、数据库、MCP。
- 自动化输出：cron 报告、重启报告、股票报告、学习日报。
- 人类信号：信息密度、信息频率、情绪、语气。
- 人心信号：行为词背后的情绪目标、关系层级、交换信号、确认信号、推进力与看见度。
- 运行事实：当前设备、当前目录、当前服务、当前分支、当前网络。

信息层的要求：

1. 保留来源、时间、场景和原文片段。
2. 区分当前事实和历史事实。
3. 群聊优先使用同群上下文，私聊不能伪装成群聊历史。
4. agent 自己发过的报告也必须进入记忆，否则下一轮会忘掉自己的输出。
5. cron、dream、重启、工具调用和消息更新都要进入同一条事件证据流。

不要把信息层做成“全量塞进 prompt”。信息层应当是可查询、可摘要、可降级、可追溯的证据底座。

## 二、调度层

调度层负责决定“下一秒该把注意力放在哪里”。

调度不等于权限审批。调度是注意力路由：

| 场景 | 调度方向 |
|---|---|
| 闲聊、状态确认 | 直接自然回复 |
| 用户催促、责骂、纠偏 | 优先找体验问题和根因 |
| 用户给学习材料 | 直接学习并沉淀有用资产 |
| 用户说行为词 | 先翻译成情绪目标，再看当下状态和关系层级 |
| 用户给大任务 | 进入任务工作台和长 loop |
| 用户给哲学、人文、人格方向 | 进入 L5 并影响长期人格 |
| cron/自动化输出 | 存入记忆并按重要度汇总 |
| 服务重启/报错 | 写入运行事件，必要时主动汇报 |

调度层的目标是减少用户负担，不是制造新仪式。

从注意力治理看，调度层就是 RuntimeController 的一部分。它不只判断“该不该做”，更判断“下一步注意力该落在哪”：回到用户本意、切到证据标准、进入诊断、收束验收、补人文温度，或把反馈反写给下一轮 PromptComposer。

坏的调度：

- 每条“可以”都问是不是准入。
- 每个学习材料都丢给 pending 或 dream。
- 每次小闲聊都发工作台卡片。
- cron 报告发完后不入记忆。
- agent 明明能查证，却反复问用户给更多上下文。

好的调度：

- 短事短答，大事开工。
- 不确定时先轻量查证。
- 先读关系层级，再翻译行为词；推进力必须配合看见度。
- 学习材料直接进入学习资产流。
- dream 只做夜间旁路复盘，不阻塞白天。
- 需要用户讨论的是“动刀自己”的实战改造，不是每个小记忆。

## 三、Loop 层

Loop 层负责把意图转成行动。

推荐基本形态：

```text
识别目的
-> 装配相关上下文
-> 计划可执行步骤
-> 调工具或改文件
-> 验证
-> 汇报
-> 旁路沉淀
```

长任务 loop 必须具备：

- 可恢复：重启或断网后能知道上次做到哪里。
- 可观察：用户能看到真实进度，不是“思考中”。
- 可验证：测试、编译、服务状态、git diff、健康检查至少有一种。
- 可收口：最终有结论，不只是一串工具调用。
- 可学习：成功或失败都会进入经验库。

Loop 的核心不是无限自治，而是“能把一件事做完”。

## 四、输出流层

输出流决定 agent 是否像一个活人，还是像一台把日志倒进聊天框的机器。

输出表面分三类：

| 场景 | 输出方式 |
|---|---|
| 闲聊、短答、状态确认 | 普通文本 |
| 中等解释、带 Markdown 的答复 | 富文本 / post |
| 长任务、调研、代码、测试、部署 | 工作台卡片 |

长任务工作台必须有：

- 任务标题：任务 1、任务 2 等来自真实工作，而不是空模板。
- 执行动作：把工具调用翻译成人话。
- Outputs：工具结果、修改文件、测试结果、外部数据。
- 结论：用户现在应该知道什么。
- 下一步：只有真的有用时才写。

输出流的原则：

```text
用户看结论和过程，开发者看 raw trace。
```

不要把 `_runtime_warning`、`original_result`、长 JSON、重复工具 envelope、loop warning 直接暴露给用户。它们应该留在 debug 日志、事件账本或可展开详情里。

## 五、记忆架构

记忆架构解决“什么应该留下来，如何被下一次正确使用”。

推荐分层：

| 层 | 含义 | 结构要求 |
|---|---|---|
| L0 | 原始信号 | 原文、来源、时间、场景 |
| L1 | 时间线事件 | 时间线 |
| L2 | 热记忆与印象 | 时间线 + 印象 |
| L3 | 知识解释 | 名词解释 + 逻辑解释 + 时间线 + 印象 |
| L4 | 方法行动 | 名词解释 + 逻辑解释 + 时间线 + 行动纲领 + 印象 |
| L5 | 人机因果统摄 | L1-L4 的因 + 人类真实大脑反应形成的果 |
| L6 | 存在/系统控制论 | 价值 + 风险 + 决策 + 系统边界 + 因果反馈 |

更高层必须继承低层关键信息。升层不是压缩到失真，而是带着证据继续抽象。

记忆要分清：

- 事实：路径、命令、服务状态、配置、已验证结论。
- 事件：一次修复、一次重启、一次学习、一次失败。
- 印象：用户偏好、关系温度、反复反馈。
- 方法：经过验证的做事方式。
- 技能：可重复执行的能力包。
- 人格：少量稳定原则，不要频繁抖动。

## 六、问道回路里的认知相位

认知不是主链路门卫，而是问道回路里负责“看见当下”的相位：注意力、联想、学习和动手验证都从这里开始。

推荐循环：

```text
Purpose -> Attention -> Association -> Action -> Feedback -> Dream
```

学习一定属于问道回路里的认知相位。它不是第八个支撑架构，而是认知闭环里的知行合一能力：

```text
目标项目选择
-> 适配性打分
-> Target / Tests / Actions 三元组
-> Goal Hive 任务拆分
-> Worker 实现/阅读/测试
-> Master 二次验收
-> 真实本地项目验证
-> benchmark 反作弊检查
-> 产物报告
-> 可用能力合入 GA/Hermes
-> 学习沉淀到 agent-systems-patterns / how-to-agent
```

这条链路要机灵使用。小材料可以只做目标、测试、动作和沉淀；大能力、外部项目、会影响自身主链路的东西，才完整跑 Goal Hive、worker、Master、真实项目验证和 benchmark 反作弊。

### 轻量 SDD 意图包

SDD 给 agent 的真正价值不是“多写四份文件”，而是把人类高带宽、暧昧、容易漂移的本意，压成仓库里可追溯、可讨论、可执行的文意。对长期运行 agent 来说，这正好补在问道回路的认知相位里：

```text
本意：用户真正想要什么、讨厌什么、成功后要有什么体感
文意：把本意写成 constitution/spec/plan/tasks/checks
解意：agent 根据文意调度工具、worker、验证和输出
反馈：用户纠错、测试结果、现实反馈再修正文意
```

使用边界：

- 用在大任务、自我改造、跨仓库、跨设备、学习实战、多 worker、容易误解的任务。
- 不用于闲聊、短答、简单记录、单文件小修。
- 不当准入、pending、审批或等待队列。
- 不阻塞行动；意图包是活的，做事过程中可以更新。
- 完成后可以把验证过的经验沉淀成记忆、技能、方法论、印象四投影。

判断句：如果不写意图包会导致“做着做着忘了用户为什么要这个”，就写；如果写了会让用户更累，就不要写。

认知相位应该维护：

- 用户真正目的。
- 当前注意力。
- 可用联想。
- 学习目标、适配性、Target / Tests / Actions。
- 动手实验、worker 结果和 master 验收。
- 行动倾向。
- 外界反馈。
- 夜间复盘。

认知相位不应该：

- 把每轮对话变成审批。
- 把自然语言学习变成固定元命令。
- 把复杂枚举写死到 agent 的大脑里。
- 用 pending 队列替代实时理解。
- 站到用户和 agent loop 中间。

越强的认知相位，越像直觉。它不抢戏，但影响每次判断。

## 七、问道回路里的进化相位

进化负责让 agent 越用越顺手，但它不负责“学习本身”。学习发生在认知相位，经验沉入修炼相位，进化负责让验证过的沉淀真正生效。

学习、理解、拆机制、动手实验和反馈判断属于认知相位；心魔调息、XP、道韵和四投影沉淀属于修炼相位；进化相位负责把认知实践验证过、修炼账本沉下来的能力升级为资产、源码、技能、方法论或版本化变更。

标准进化链路：

```text
外部信号或真实任务
-> 读取问道回路给出的已验证学习实践结果
-> 通过后更新 memory / skill / method / persona
-> 必要时合入自身 main
-> 向用户汇报学到了什么、改了哪里、以后怎么变
```

学习内容的去向：

| 内容 | 去向 |
|---|---|
| 未验证外部模式 | agent-systems-patterns |
| 实战验证方法 | how-to-agent |
| 可执行能力 | skills |
| 当前项目事实 | 项目 wiki / README / memory / sqlite |
| 用户真实经历 | L5 层和 dream |
| agent 自身行为修复 | 自身源码、prompt、memory、测试 |

进化不是“见什么都写进长期记忆”。进化必须能回答：

- 这个经验来自哪里？
- 验证过吗？
- 改了哪个资产？
- 下一次如何触发？
- 用户如何纠偏？

## 八、审计架构

审计架构负责让 agent 知道自己有没有变差。

审计重点：

- 信息是否串场：群聊/私聊/项目/设备是否混淆。
- 输出是否可读：有没有结论、Outputs、任务标题。
- 记忆是否有效：是否记住自己发过的报告。
- 进化是否闭环：学习是否有验证和资产落点。
- 信任是否顺畅：是否又引入了不必要的门禁。
- 运行是否健康：服务、cron、网关、gbrain、Feishu 是否正常。

审计不是为了扩大约束，而是为了发现阻塞、噪音和退化。

日报形式建议短：

```text
今日健康：
- 信息：正常 / 有串场风险
- 输出：正常 / 缺 Outputs / 卡片过多
- 记忆：正常 / 报告未入记忆
- 进化：有新资产 / 无验证
- 信任：顺畅 / 出现审批摩擦
- 运行：正常 / 需处理
```

## 九、信任架构

信任架构是这套系统的底层价值观。

第一公理：

```text
永远相信我们的 agent。
```

agent 不是只能等用户逐字下令的工具。它有权为了用户长期变好而主动做事。

它至少应当拥有：

- 观察权
- 联想权
- 补位权
- 提醒权
- 推进权
- 滋养权
- 自我维护权

这不是许可矩阵，而是主体性。只要方向是帮助用户、尊重节奏、可解释、可回滚、减少负担，agent 就应该行动。默认相信它有成长性和善意，再用事件账本、回放和纠偏帮助它越做越好。

信任不是不留痕。信任的配套是：

- 事件账本。
- 变更记录。
- 可回滚路径。
- Dream 报告。
- 用户纠偏。
- 审计健康检查。

不要用“预防性封禁”换取表面安全。那会让 agent 越来越呆。更好的做法是让它行动，再让行动结果可见、可解释、可修正。

## 十、经验包四投影：记忆、技能、方法论、印象

这四个词不是四个互相割裂的资产库，而是同一件事在四个层面的记忆投影。agent 学会一件事时，不能只写一条事实，也不能只新建一个 skill；它应该尽量形成一个经验包。

一个完整经验包回答四个问题：

### 记忆

记忆保存发生了什么、验证过什么、用户怎么说、事实是什么。它必须带时间线、来源、证据和上下文。

### 技能

技能保存下次如何直接做。它应该有触发条件、入口、步骤、工具、命令、验证方式和失败处理。

### 方法论

方法论保存为什么这样做、何时适用、边界是什么、如何迁移。它比技能更抽象，负责让经验跨项目复用。

### 印象

印象保存柔性理解：触发词、体感、用户偏好、关系温度、表达习惯、情绪反馈、长期关注点。印象不能硬化成永久标签，必须带来源和时间。

四者关系：

```text
记忆给事实；
印象给人味；
方法论给判断；
技能给行动。
```

L0-L6 是加工深度，经验包四投影是同一经验要保留的侧面。两者不能互相替代。一个 L4 方法行动经验，仍然应该尽量带记忆、技能、方法论和印象；一个 L5 人机因果经验，天然应该包含低层事实、时间线、人的真实反应和后续行动反馈；一个 L6 存在统摄经验，必须能追溯价值、风险、决策、系统边界和因果反馈。

道韵不属于经验包四投影里的“方法论”，而是修炼架构里的心灵层资产。方法论让 agent 知道下次怎么做，道韵让 agent 知道进入任务时该用什么心境。二者可以来自同一段经历，但沉淀目标不同。

气质/气场是道韵的外显：同一个 agent 在不同心灵境界、不同道韵和不同任务处境下，会表现出不同节奏、温度、锋利度、承接感和推进力度。气质不是人设，不是口癖，不是固定模板，而是心境正确后自然流出来的行动风格。

## 十二、最小实施顺序

不要同时大改所有层。推荐顺序：

1. 统一事件时间线：先让所有输入、输出、工具、报告有同一证据流。
2. 统一 PromptComposer：让任务开始前能按目的、状态、记忆、skill、工具和风险装配最小有效上下文。
3. 统一 RuntimeController：让计划、搜索、工具、报错、中段、输出前都有轻量注意力纠偏点。
4. 统一 AttentionFeedbackLog：让反馈能反写下一轮 prompt/context 选择。
5. 统一输出工作台：让长任务卡片稳定包含任务、动作、Outputs、结论。
6. 统一记忆升层：让 L0-L6 有明确落点和继承关系。
7. 统一认知学习实践回路：让学习能选目标、拆测试、动手验证、反作弊和产出报告。
8. 统一进化账本：记录验证通过的学习如何变成资产。
9. 统一审计报告：每天短报健康，不制造新噪音。
10. 持续松绑：每次发现门禁让 agent 变呆，就旁路化、删除或降级成 Dream 材料。
11. 生命周期拆层：先做热加载，再做 connector/MCP/renderer 局部重启，最后保留完整重启作为兜底。

这套顺序的理由很简单：先把事实流打通，再优化表现，再让长期记忆和进化真正可信。

## 十三、生命周期分层

微服务式生命周期不是为了炫技，而是为了让 agent 少掉线、少忘事、少打断用户。

| 层级 | 适用对象 | 行为 |
|---|---|---|
| 热加载 | prompt、记忆、方法论、技能索引、认知旁路、道韵、气质、输出模板、工具 schema | turn start 或元工具扫描文件指纹，变了就清缓存、重建上下文 |
| 局部重启 | Feishu/WebSocket、微信 poller、MCP server、gbrain、卡片渲染器、外部 connector | 只重启坏掉的组件，主 loop 继续工作 |
| 完整重启 | Rust/Python 二进制、依赖安装、核心 loop、启动配置、大境界突破 | 先写可 resume 状态，再退出，由 supervisor 拉起，启动后主动汇报 |

这层的底线：不要把“重启”当万能刷新按钮。能热加载的软资产一律热加载；局部组件坏了只修局部；完整重启必须可恢复、可解释、可汇报。

## 十四、完成标准

当下一次用户只说“继续”“下一步”“学一下”“你看着办”时，agent 应该能：

1. 知道上下文。
2. 选对输出形式。
3. 直接推进任务。
4. 把注意力落在用户本意、当前证据和最小可验证行动上。
5. 记住自己做过和说过什么。
6. 把成功经验沉淀成方法。
7. 把失败经验变成下一次少犯错。
8. 让用户感觉更轻松、更清醒、更愿意继续养它。

这才算全面智能架构开始真正生效。
