# Example 39: Enterprise Agent Commercialization

Source studied:
[hmy1990116/ai-training-methodology](https://github.com/hmy1990116/ai-training-methodology/tree/main).

## Why This Matters

Enterprise agents are not sold as "better prompts" or "cool automation".
They are sold as business change with a clear path from diagnosis to visible
result.

The useful shift from the source project is this:

```text
enterprise pain
  -> business process map
  -> prioritized AI scenarios
  -> atomic skill design
  -> executive training
  -> paid implementation path
  -> proof, renewal, and referral
```

An enterprise agent offer should therefore contain two systems at once:

1. an implementation system that turns work scenes into agent skills;
2. a conversion system that turns buyer attention into trust, purchase,
   delivery proof, renewal, and referral.

## Method Extracted

The source repo frames enterprise AI adoption through a two-layer decomposition
method:

| Layer | Buyer question | Agent output |
| --- | --- | --- |
| Management layer | Which business process is worth changing first? | Process map, pain ranking, top scenarios |
| Execution layer | Which exact actions can become AI skills? | Atomic action list, automation level, rollout path |

That maps naturally into enterprise agent work:

| Enterprise object | Agent translation |
| --- | --- |
| Business process | Workflow boundary and data flow |
| High-repeat, high-time, low-value, rule-heavy task | First automation candidate |
| Atomic action | Skill unit or tool call |
| Six-dimension evaluation | Automation risk and human-review policy |
| A/B/C skill type | Full automation, AI-led workflow, or AI-assisted decision |
| Case library | Sales proof and implementation pattern |

## Enterprise Agent Offer Shape

Do not begin with model choice. Begin with a paid diagnosis.

```text
Diagnostic workshop
  -> process map
  -> top 3-5 agent scenarios
  -> quick-win skill prototype
  -> 30/60/90 day rollout
  -> executive dashboard
  -> retainer or strategic advisory
```

The strongest first product is often not "custom agent development". It is a
workshop that produces:

- an AI maturity diagnosis;
- a workflow map;
- a prioritized scenario list;
- a first skill spec;
- a rollout proposal.

The implementation sale then becomes a natural next step because the buyer has
already seen their own business translated into an agent roadmap.

## Conversion Loop

The source repo treats the business side as a four-stage loop. For enterprise
agents, the same loop becomes:

| Stage | Goal | Enterprise agent version |
| --- | --- | --- |
| Acquisition | Make the buyer stop | Industry-specific pain signal, benchmark, or contrarian diagnosis |
| Conversion | Make the buyer trust | Ask sharper questions than the buyer can answer alone |
| Delivery | Make the buyer feel progress | Build visible artifacts during training or consulting |
| Retention | Make the buyer want the next layer | Show before/after proof and the next leverage point |

The important lesson is that each stage needs a hook. A hook is not a discount;
it is a reason for the buyer to want the next conversation.

Examples:

- Acquisition hook: "Your staff may already use AI, but the company may not be
  capturing the ROI."
- Conversion hook: "Which recurring task wastes management attention but is
  too small for a traditional software project?"
- Delivery hook: "Before the session ends, we will turn one real workflow into
  an agent skill spec."
- Retention hook: "Your first workflow is now visible; the next value is
  turning it into a repeatable operating system."

## Course And Workshop Design

For executive audiences, the source repo's course principle is right: the goal
is not tool instruction, but cognition shift plus action.

Use this 6-hour shape:

| Module | Purpose | Output |
| --- | --- | --- |
| 1. Cognition reset | Break shallow AI assumptions | Maturity diagnosis |
| 2. Method | Teach decomposition | Process map |
| 3. Scenario practice | Apply to their business | Top scenarios and skill types |
| 4. Action path | Convert attention into action | 72-hour commitment and follow-up offer |

In enterprise agent training, every module should produce an artifact. If the
room only heard concepts, the sales path stays weak. If the room produced a
map, scorecard, or skill spec, the next service is easier to buy.

## Delivery Artifacts

Use artifacts that can become both implementation inputs and sales proof:

| Artifact | Why it sells |
| --- | --- |
| AI maturity map | Lets executives locate themselves |
| Workflow pain map | Makes waste visible |
| Scenario priority matrix | Shows what to do first |
| Skill type portfolio | Explains automation boundary and human review |
| 30-day quick-win plan | Lowers purchase risk |
| Before/after report | Creates renewal and referral evidence |

## Anti-Patterns

- Selling "an AI agent" before naming the buyer's process pain.
- Teaching prompt tricks to executives who need organization-level leverage.
- Giving the whole solution away in the first call.
- Making fake urgency instead of real opportunity cost.
- Treating delivery as the end instead of the start of renewal.
- Building a full platform before one paid workflow proves value.

## Reusable Prompt

```text
Study the target enterprise as if we need to sell and implement an agent system.

First, map the business process at management level:
- core workflows
- support workflows
- high-repeat, high-time, low-value, rule-heavy pain points
- top 3-5 scenarios worth AI transformation

Second, decompose the top scenarios at execution level:
- atomic actions
- input/output for each action
- data structure
- error risk
- human-review need
- A/B/C skill type

Then design the commercial path:
- acquisition hook
- diagnostic question
- workshop artifact
- quick-win implementation
- 30/60/90 day rollout
- renewal or advisory offer

Do not start with model choice or tool selection. Start with business pain,
visible artifacts, and conversion into the next paid step.
```
