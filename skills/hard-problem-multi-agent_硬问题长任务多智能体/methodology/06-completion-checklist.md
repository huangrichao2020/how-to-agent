# Methodology 06 · 完成检查清单

> 来源：Crouzeix 任务的"完成才停止"原则

## 核心问题

"我什么时候才算做完了？"

Crouzeix 任务的答案：**只有完整解 + 通过对抗审计 + 形式化验证 + 至少一轮简化，才算完成**。

下面是发布前必须勾选的清单。

## 必检清单（10 项）

### 1 · 完整解已构造

- [ ] 主命题的完整证明已写出（不只是 reduction）
- [ ] 没有"isolated missing lemma"（孤立缺失引理）
- [ ] 没有"partial result"（部分结果）
- [ ] 没有"best effort summary"（尽力了总结）
- [ ] 没有"explanation of why the problem is difficult"（问题很难的解释）

**反例（**不**算完成）**：
- "我证明了一个特例"
- "我把问题归约到了 X"
- "X 是开放的，我尽力了"
- "这看起来很对，但我没完全验证"

### 2 · 所有公开假设都已证明

- [ ] 主证明中所有显式假设都有引用或证明
- [ ] 没有任何 "assume X holds" 而 X 未证
- [ ] 没有任何 "by symmetry" / "WLOG" 的隐藏假设

**反例**：
- "假设矩阵可对角化" —— 如果没证明只对可对角化矩阵成立
- "不失一般性，假设 ..." —— WLOG 的合法性未验证

### 3 · 所有"显然"步骤都已严格化

- [ ] 搜索所有"显然"、"易证"、"显然成立"等措辞
- [ ] 对每一处，要么写出完整证明，要么引用已知定理
- [ ] 没有 "类似的" / "其他情况类似"

**反例**：
- "易证 Y ≤ X" —— 实际上不是显然
- "显然满足条件 Z" —— 实际上条件 Z 不满足

### 4 · 通过对抗审计

- [ ] 对抗 agent 已审查 v_n
- [ ] 报告的所有真漏洞已修复
- [ ] 报告的假漏洞已被反驳（不是默默忽略）
- [ ] 审计报告已归档（`MANUSCRIPT_AUDIT.md`）

**审计产物**：
- `MANUSCRIPT_AUDIT.md` —— 数学审计
- `AXIOM_AUDIT.md` —— 公理依赖
- `FORMALIZATION_MAP.md` —— 源-形式化对应
- `CONTINUATION_STATUS.md` —— 当前状态

### 5 · 形式化验证通过（如适用）

- [ ] 所有声明已用 Lean 4 / Coq / 等形式化
- [ ] `lake build` 通过
- [ ] `AXIOM_AUDIT` 仅依赖标准公理
- [ ] 无 `sorry` / `admit` / 自定义 axiom
- [ ] 无 unsafe 构造 / native-decision / 警告抑制

**形式化范围**：
- 必做：数学证明 / 算法正确性
- 推荐：协议 / 系统设计
- 可选：物理 / 工程定理

### 6 · 公理依赖已审查

- [ ] 所有用到的公理列在 `AXIOM_AUDIT.md`
- [ ] 每个公理都说明为什么可接受
- [ ] 没有自定义公理（除非有充分理由）

**标准公理（Lean 4）**：
```
propext
Classical.choice
Quot.sound
```

**自定义公理（必须说明）**：
- 为什么需要
- 为什么不与标准公理冲突
- 是否可弱化

### 7 · README 含构建步骤 + 状态 + AI 协助声明

- [ ] README 写明当前状态（什么已完成、什么待审）
- [ ] README 含构建步骤（用户能复现）
- [ ] README 含 AI 协助声明（"OpenAI ChatGPT contributed to..."）

**README 模板**：

```markdown
# 项目名

[一句话说明这是什么]

## Status

- [已完成项 1]
- [已完成项 2]
- [待审/待完成项]

## Contents

- [文件 1]: [说明]
- [文件 2]: [说明]

## Build

[构建命令]

## AI assistance

[AI 工具 + 协助范围]
```

### 8 · Git history 保留所有失败版本

- [ ] v1 / v2 / v3 都在 git history
- [ ] 工作树只有 v_n（稳定版）
- [ ] 失败/废弃版本未被强制删除

**关键**：失败版本是教训，丢了找不回来。

### 9 · 主稿件可独立编译

- [ ] LaTeX 文件可独立编译（不依赖未声明的文件）
- [ ] Lean 项目可独立构建（依赖在 manifest 里）
- [ ] 没有引用未上传的资源
- [ ] PDF 输出稳定（运行 `latexmk -pdf` 一次过）

### 10 · 至少一轮简化迭代

- [ ] 有 v1 和 v2 的差异
- [ ] v2 比 v1 更简单（代码/论证）
- [ ] 简化理由记录（commit message）

**验证简化是真实进步**：
- 删除的引理数 ≥ 新增的引理数
- 主证明路径改变（不是 typo 级别）
- 对抗审计在 v2 找不出 v1 的漏洞

## 软指标（非强制但推荐）

### 写作质量

- [ ] 章节标题清晰
- [ ] 关键定义在首次出现处有解释
- [ ] 引用规范（annmath / 自定义）
- [ ] 图表有编号和说明

### 可重现性

- [ ] 提供复现脚本
- [ ] 提供数据/输入（如果是计算证明）
- [ ] 提供随机种子（如果是概率证明）

### 案例库归档

- [ ] 把这个项目归档到 case-study/
- [ ] 提炼通用方法论
- [ ] 与已有 skill 关联

## 完成 vs "差不多完成" 的判断

| 状态 | 表现 | 是否完成 |
|---|---|---|
| 主证明写完 | 主稿件 LaTeX 可编译 | ❌ 不算（未审计、未简化）|
| 主证明写完 + 对抗审计 | 已审查、已修复漏洞 | ❌ 不算（未简化）|
| 主证明 + 审计 + v2 | v2 比 v1 更简单 | ✅ 算 |
| 主证明 + 审计 + v2 + Lean | Lean 通过、axiom audit 通过 | ✅✅ 强完成 |
| 主证明 + 审计 + v2 + Lean + 投稿 | Annals 投稿已发 | ✅✅✅ 发布完成 |

**关键**：v_n 发布前**必须**满足至少 ✅ 算（v2 + 审计）。

## 实战要点

### 不要宣布完成过早

```
- v1 完成 ≠ 任务完成
- 对抗审计通过 ≠ 任务完成
- Lean 形式化通过 ≠ 任务完成
- 只有"完整证明 + 通过审计 + 通过形式化 + 至少一轮简化"才算完成
```

### "完成"是相对的

不同任务的"完成"标准不同：
- 数学证明 → 必须有 Lean 形式化
- 系统设计 → 必须有对抗审计
- 软件架构 → 必须有形式规约
- 论文写作 → 同行评议通过

**原则**：**严格度匹配任务难度**。数学证明比系统设计更难，所以门槛更高。

### 不要偷偷"差不多完成"

如果发现自己说"差不多了"、"应该可以"、"看起来对"——立即停止，回到清单逐项检查。

## Crouzeix 项目的最终状态

```
Status:
- Candidate proof written as standalone LaTeX manuscript ✓
- Several independent computational and adversarial audits found no specific mathematical error ✓
- Formal peer review is still pending ⏳
```

**这是诚实的"完成"声明**：
- ✅ 候选证明已写
- ✅ 多轮审计未发现错误
- ⏳ 同行评议（Annals）待审

**没有说**：✅ 证明正确 → 因为 peer review 才是最终判定。
