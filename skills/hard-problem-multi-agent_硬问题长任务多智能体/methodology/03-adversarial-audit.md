# Methodology 03 · 对抗审计机制

> 来源：Crouzeix 任务的 "Use adversarial agents throughout: every candidate proof must be checked for gaps, conditionals, handwavings, and circular uses of an equivalent statement."

## 核心思想

**对抗审计不是"挑错"，而是"找真错"**。它要求 agent 站在敌对方，主动寻找漏洞。

| 角色 | 立场 | 任务 |
|---|---|---|
| 正审计 | 敌对 | 找漏洞、错误、遗漏 |
| 反审计 | 友方 | 反驳漏洞（如果漏洞不真实）|
| 最终审计 | 中立 | 判定 v_n 是否可发布 |

## 4 类必查问题

### 1 · gaps（推理跳跃）

**特征**：
- "显然" / "易证" / "对称性可知"
- "由读者自证" / "此处省略"
- 从 A 直接跳到 C 没解释 B

**审计 prompt**：
```
找出所有标有"显然"、"易证"、"对称性可知"、"显然成立"、
"标准"等措辞的地方。
对每一处，明确说明：
- 它是否真的是显然？如果不显然，写出完整证明
- 它依赖什么未证明的引理？
- 它能否用更弱的假设证明？
```

### 2 · conditionals（假设未验证）

**特征**：
- "假设 X 成立" —— X 是否真的成立？
- "若不然"分支 —— 这个分支是否真的处理了？
- "可推广到" —— 推广条件是否满足？

**审计 prompt**：
```
列出所有显式和隐式的假设。
对每个假设，问：
- 这个假设真的成立吗？
- 它在主证明中被验证过吗？
- 是否有反例？
- 它能否弱化？
```

### 3 · handwavings（手挥论证）

**特征**：
- "类似可证"
- "其他情况类似处理"
- "此处与...同"
- 跳过完整证明给出"关键步骤"

**审计 prompt**：
```
找出所有说"类似"、"其他情况类似"、"与...同"的地方。
对每一处，写出完整证明。
```

### 4 · circular uses（循环使用）

**特征**：
- 用了等价于待证命题的结论
- "由待证命题立即推出"
- 用了**证明目标本身**作为前提

**审计 prompt**：
```
对每个关键引理，问：
- 它是否比原命题更强？
- 它是否等于原命题？
- 它是否在证明过程中被等价使用？
- 如果删掉这个引理，证明还能成吗？
```

## 审计轮次

| 阶段 | 审计轮次 | 主要动作 |
|---|---|---|
| v1 | 3-5 轮 | 找漏洞、修漏洞、再找 |
| v2 | 2-3 轮 | 简化、删冗余、再简化 |
| v3 | 1-2 轮 | 找更弱假设、改进表述 |
| v4 | 1 轮（最终）| 发布前确认 |

**每轮审计 prompt 模板**：

```
你是这个证明的对抗审计 agent。
任务：找出以下 4 类问题——
1. gaps: 推理跳跃（"显然"等）
2. conditionals: 假设未验证
3. handwavings: 手挥论证（"类似"等）
4. circular uses: 循环使用

对每一处，给出：
- 位置（行号/段落）
- 类型（4 类之一）
- 问题描述
- 修复建议（具体怎么修）
- 是否是真问题（如果是"假漏洞"，说明为什么不算）

回报格式：
### 漏洞 1
- 位置: ...
- 类型: ...
- 描述: ...
- 修复: ...
- 真伪: ...
```

## 反审计（反驳漏洞）

每个漏洞要被挑战两次：
1. 正审计："这是漏洞"
2. 反审计："这不是漏洞，因为 X"

**反审计 prompt 模板**：
```
对于审计 agent 报告的每一个漏洞：
- 它是真漏洞吗？
- 能否用更弱的论证修复？
- 能否用不同的假设绕过？
- 如果是数学证明，能否用例子反驳？

回报：
### 漏洞 1
- 正方审计报告: ...
- 反方反驳: ...
- 最终判定: 真漏洞 / 假漏洞 / 部分真
```

## 最终审计（判定发布）

最终审计做 3 件事：
1. 检查所有漏洞是否已修复
2. 检查所有公理依赖是否合规
3. 检查所有声明是否已形式化

**通过标准**：
- 0 个未修复的真漏洞
- 公理依赖仅在标准库
- 形式化验证通过
- 主稿件可独立编译
- 至少一轮简化迭代

**不通过标准**（任一即不通过）：
- 1 个未修复的真漏洞
- 1 个自定义公理
- 1 个 sorry/admit
- 0 轮简化迭代

## 实战要点

### 不要在最后才审计

- v1 → 立即审计
- v2 → 立即审计
- v3 → 立即审计
- v4 → 最终审计

每轮迭代后立即审计，不要攒到最后。

### 对抗审计 agent 必须独立

- 对抗 agent 不能与正方 agent 共享上下文
- 对抗 agent 必须能"自己复现证明"才能找漏洞
- 如果对抗 agent 找不出漏洞 → 警惕（可能审计力度不够）

### 真假漏洞的判断

| 漏洞类型 | 真假判定 |
|---|---|
| "你说 X 显然，但 X 不显然" | 通常为真漏洞 |
| "你说有循环，但实际是单向引用" | 通常为假漏洞 |
| "你说条件缺失，但条件隐藏在另一个引理里" | 通常为假漏洞（但要明确指出）|
| "你说有反例，但反例不满足前提" | 通常为假漏洞 |
