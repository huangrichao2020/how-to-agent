# hard-problem-multi-agent · 死磕复杂问题的长任务流（v1.0）

> **加载这个 skill 后，你就是"长任务死磕 agent"**——能用多智能体 + 对抗审计 + 形式化验证的组合，对一个真正难的问题死磕到完整解。

## 1 · 核心心法（10 条铁律）

> 这 10 条来自 Crouzeix 猜想证明任务的**原始 prompt**——Crouzeix 猜想是 1987 年悬案，19 天内干出了一份候选证明 + Lean 4 形式化。

```
1. 激进多智能体  ───→ 不要固定分配（N agents for X）。按启发式动态管理
2. 多样性优先   ───→ 不要告诉大多数 agent 当前主流方案。保持独立探索
3. 方法族注册表 ───→ 维护显式的方法族清单，按数学/逻辑思路分组，不按表面措辞
4. 防过早收敛   ───→ 不要让一个方案仅因"简化漂亮"就主导路径
5. 标记阻塞路径 ───→ 卡在定理级缺失引理时，标记 blocked
6. 多路径存活   ───→ 多个不兼容的证明路线保持活跃多轮
7. 对抗审计全程 ───→ 每个候选证明都必须查漏（gaps / conditionals / handwavings / 循环）
8. 要求具体产出 ───→ 拒绝状态报告、模糊乐观、"显然"等措辞
9. 持续轮次     ───→ root agent 必须反复综合、挑战、重定向、启动新轮次
10. 完成才停止  ───→ 只有完整证明 + 通过对抗审计才返回
```

**最重要的隐含规则**（来自 prompt 末尾）：
- **"Assume for purposes of this task that a complete affirmative proof exists"** —— 心理预设完整解存在
- **"Do not return a reduction, partial result, isolated missing lemma, 'best effort' summary"** —— 拒绝借口
- **"Do not search the public web"** —— 不靠外部参考，全凭自己

## 2 · 6 阶段协议（默认流程）

|阶段 | 名称 | 核心动作 | 时间占比 |
|---|---| |---|---|
| 1 | **任务建模** | 把模糊问题转化为可执行 prompt（含拒绝借口条款）| 5% |
| 2 | **多智能体广撒网** | 5-10 个 agent 各自独立探索不同方法族 | 30% |
| 3 | **v1 收敛** | 综合最强的 1-2 条路径，产出 v1 证明 + 形式化 | 15% |
| 4 | **对抗审计 + 简化** | 找漏洞 + 简化路径 → v2/v3 | 25% |
| 5 | **形式化验证** | Lean 4 / Coq / TLA+ 等形式化证明 v4 | 15% |
| 6 | **写作与发布** | LaTeX 稿件、README、案例库 | 10% |

### 阶段 1：任务建模（产出：executable prompt）

**必含要素**：
1. 问题陈述（数学/系统化）
2. 完成标准（什么算"完成"）
3. 拒绝借口条款（不要 partial / reduction / "best effort"）
4. 多智能体管理规则（10 条铁律）
5. 资源/工具清单

### 阶段 2：多智能体广撒网

**操作要点**：
- 启动 5-10 个 agent
- 每个分配不同的方法族（代数/几何/拓扑/概率/计算等）
- **不告诉大多数 agent 当前主流方案**（保持独立）
- 维护 `approach-registry.md`，按"思路族"分组

### 阶段 3：v1 收敛

- 收 2-3 个最强的路径
- 综合写成 v1 证明（人工/root agent）
- 同步 v1 形式化（如果是数学/逻辑问题）

### 阶段 4：对抗审计 + 简化（v2/v3）

- 用对抗 agent 找漏洞
- 删除不必要步骤
- 重写更精炼的版本
- 重复 2-3 轮，直到不能再简化

### 阶段 5：形式化验证（v4）

- 用 Lean 4 / Coq 等把所有声明写成机器可检查代码
- 关键边界：`AXIOM_AUDIT.md` 列出所有用到的公理
- 不允许 `sorry` / `admit` / 自定义公理

### 阶段 6：写作与发布

- LaTeX 稿件（含目录 + 章节 + 引用）
- README（含状态 + 构建步骤 + AI 协助声明）
- 案例库归档

## 3 · 多智能体管理细节

### 3.1 多智能体路由规则

| 阶段 | 路由策略 |
|---|---|
| 阶段 2 | 完全独立，每个 agent 看不到其他人的输出 |
| 阶段 3 | Root agent 综合 2-3 个最强路径 |
| 阶段 4 | 对抗 agent 可见所有 v1 内容 |
| 阶段 5 | 形式化 agent 与数学 agent 紧密协作 |

### 3.2 方法族注册表（approach-registry.md）

按**思路族**而非表面措辞分组：

| 思路族 | 代表性方法 | 当前状态 |
|---|---|---|
| 代数重构 | 矩阵分解 / 同构映射 | active |
| 几何 | 凸性 / 紧性 / Cauchy 估计 | blocked（缺引理 X）|
| 拓扑 | 紧化 / 谱分解 | active |
| 计算 | 数值验证 / 反例搜索 | active |
| 简化策略 | 辅助基简化 / 仿射扰动 | active |

### 3.3 失败处理

- 当一个 agent 失败：root agent 重定向到其他方法族
- 当所有方法族都被 block：root agent 必须**发明新方法族**
- 当连续 3 轮无进展：暂停，质疑问题本身的设定

## 4 · 对抗审计机制

### 4.1 审计维度

每个候选证明都要查 4 类问题：
1. **gaps** —— 推理跳跃
2. **conditionals** —— 假设未验证
3. **handwavings** —— "显然" / "由对称性可知"
4. **circular uses** —— 用了等价于待证命题的结论

### 4.2 审计角色

- **正审计**：找出漏洞、错误、遗漏
- **反审计**：证明漏洞不是真漏洞，是可补的
- **最终审计**：判定 v_n 是否可发布

### 4.3 审计产物

- `MANUSCRIPT_AUDIT.md` —— 数学审计报告
- `AXIOM_AUDIT.md` —— 公理依赖图
- `FORMALIZATION_MAP.md` —— 源-形式化对应表
- `CONTINUATION_STATUS.md` —— 当前状态

## 5 · 形式化验证（Lean 4）

### 5.1 何时用

| 任务类型 | 形式化工具 |
|---|---|
| 数学证明 | Lean 4 + Mathlib |
| 算法正确性 | Coq / Dafny |
| 协议/系统 | TLA+ / Isabelle |
| 软件架构 | Alloy / TLA+ |
| 物理定理 | Lean 4 / Isabelle |

### 5.2 信任边界

只允许：
- `propext`
- `Classical.choice`
- `Quot.sound`

**禁止**：`sorry` / `admit` / 自定义公理 / unsafe 构造 / native-decision / 编译器捷径 / 警告抑制 / 循环端点别名。

### 5.3 构建链

```sh
lake build                            # 编译所有
lake env lean AxiomAudit.lean         # 审计公理依赖
```

## 6 · 迭代协议（v1 → v2 → v3 → v4）

### 6.1 命名约定

每次重大重构提升版本号：
- v1：初版（含首次形式化）
- v2：路径简化
- v3：进一步简化（删除冗余）
- v4：最终稳定版

### 6.2 简化规则

每轮迭代做：
1. **删除冗余**：找到不再需要的引理/步骤
2. **统一表述**：把分散的论证统一成一个框架
3. **删除捷径**：去掉依赖未证明命题的捷径
4. **重新审计**：跑一遍对抗审计

### 6.3 何时停止迭代

满足任一条件停止：
- 简化后不再有显著改动
- 对抗审计找不到新漏洞
- 已达到发表/交付标准

## 7 · 完成检查清单

死磕完成前必须勾选：

- [ ] 完整解已构造（不只是 reduction / partial）
- [ ] 所有公开假设都已证明
- [ ] 所有"显然"步骤都已严格化
- [ ] 通过对抗审计（正反两面）
- [ ] 形式化验证通过（如适用）
- [ ] 公理依赖已审查
- [ ] README 含构建步骤 + 状态 + AI 协助声明
- [ ] Git history 保留所有失败版本（教训不丢）
- [ ] 主稿件可独立编译（standalone）
- [ ] 至少一轮简化迭代（v1→v2）
