# Structured Prompt Engineering (结构化提示工程)

## 核心原则 (8条)
1. **明确角色与任务**：开篇定义 AI 的身份（如“资深交易员”）和具体目标。
2. **完整背景信息**：将所有固定规则、表单结构放入 System Prompt，减少重复输入。
3. **结构化组织**：按 `背景 → 输入数据 → 推理步骤 → 约束条件 → 输出格式` 组织内容。
4. **复杂任务拆解**：将大任务拆分为明确的子步骤（Step-by-step），引导模型逐步推理。
5. **示例引导 (Few-shot)**：对于严格格式或术语，提供 1-2 个输入输出示例。
6. **防幻觉约束**：明确要求“不确定时不要猜”、“必须引用输入数据中的依据”。
7. **预填输出格式**：直接给出 JSON 框架，让模型填空，便于程序化处理。
8. **扩展思考 (Extended Thinking)**：对复杂逻辑开启深度思考模式。

## 实战模板 (Info-Hub 个股分析版)

```markdown
## 角色与任务
你是一位拥有 20 年经验的 A 股交易员。请根据提供的量化数据对【{code}】进行分析。

## 输入数据
### 1. 基础信息
- 代码：{code}
- 最新价：{price}

### 2. 技术面
```json
{kline_data}
```

## 分析步骤
1. **趋势判断**：结合 MA5/MA20 判断当前是上升还是震荡。
2. **量价验证**：对比成交量与均量，确认资金态度。
3. **综合结论**：给出评级和操作建议。

## 约束（防幻觉）
- **严禁编造数据**：所有结论必须有上述输入数据作为依据。如果数据缺失，标注“数据不足”。
- **客观中立**：完全基于量价事实说话。

## 输出格式
请严格输出以下 JSON 格式：
{{
    "rating": "看多/看空/震荡",
    "confidence": "高/中/低",
    "technical_view": {{
        "trend": "上升/下降/震荡",
        "support_level": 数值
    }},
    "action_plan": {{
        "buy_condition": "...",
        "stop_loss": 数值
    }}
}}
```

## 实施要点
- **变量注入**：在 Python 中使用 f-string 注入动态数据，但保持 Markdown 结构的完整性。
- **JSON 提取**：在代码层使用 `response.find('{')` 和 `rfind('}')` 提取有效 JSON，容错 LLM 的多余废话。
- **迭代优化**：根据 LLM 返回的错误类型（如幻觉、格式错误）不断微调“约束”部分。
