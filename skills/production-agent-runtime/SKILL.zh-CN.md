# 生产级 Agent 运行时

[English](SKILL.md) · [简体中文](SKILL.zh-CN.md)

本 skill 提炼自 GenericAgent (GA) 和 Hermes 在开发者机器上作为持久化、物理级执行 agent 的实践经验。涵盖三层架构、分层记忆系统、联邦委托、失败升级协议和自愈机制。

## 核心架构

生产级 agent 应该将职责分为三层：

```
┌─────────────────────────────────────────────────────┐
│                   用户交互层                          │
│  飞书/Slack/终端/Web/定时任务                          │
└──────────────────────┬──────────────────────────────┘
┌──────────────────────▼──────────────────────────────┐
│                   核心引擎                            │
│  工具路由 · 历史管理 · 记忆管理 · LLM 调度 · 安全护栏   │
└──────────────────────┬──────────────────────────────┘
┌──────────────────────▼──────────────────────────────┐
│                  联邦委托层                           │
│  子 Agent · Swarm · 外部 CLI · 浏览器 CDP              │
└─────────────────────────────────────────────────────┘
```

### 各层职责

1. **交互层**：不同前端的适配器（飞书/Lark、Slack、终端、Web）。每个适配器处理平台特定的消息格式、@mention 和媒体。核心引擎应与前端无关。

2. **核心引擎**：大脑。管理工具路由、对话历史、记忆注入、LLM 调度和安全护栏。应该是单一进程，有清晰的入口/出口。

3. **联邦委托**：当工作独立或需要隔离时，生成子会话（子 agent、swarm、外部 CLI）。每个子进程有受限权限和明确目标。

## 分层记忆系统

生产级 agent 需要分层记忆模型，避免上下文溢出的同时保留持久知识：

| 层级 | 名称 | 存储 | 生命周期 | 用途 |
|------|------|------|----------|------|
| L0 | META-SOP | `memory/README.md` | 永久 | 如何管理记忆本身 |
| L1 | 瞬时记忆 | Session history | 会话级 | 即时上下文、工具结果 |
| L2 | 事实记忆 | `global_mem.txt`, `MEMORY.md` | 长期 | 环境事实、用户偏好 |
| L3 | SOP | `*_sop.md` 文件 | 长期 | 标准操作流程 |
| L4 | 归档 | `daily/`, `L4_raw_sessions/` | 永久 | 决策日志、原始会话记录 |

### 记忆规则

1. **先搜索**：行动前检查记忆中是否已有约束或事实。
2. **先读后写**：修改文件前必须先读取。
3. **只保留活跃规则**：删除或跳过已落地到代码/配置中的事实。
4. **不存已完成工作日志**：记忆存储仍需遵循的规则/事实，不是已完成工作的历史。
5. **用 patch 而非覆盖**：对记忆文件使用定向 patch，除非创建新文件。

## 失败升级协议

永远不要盲目重试。遵循这个升级阶梯：

1. **第 1 次失败**：读取错误输出，理解失败原因。
2. **第 2 次失败**：探测环境状态（检查进程、文件存在性、权限、网络）。
3. **第 3 次失败**：深度分析，然后切换策略或询问用户。

**没有新信息的情况下，不要重复操作。**

## 自愈与重启

- 长时间工作前保存当前任务、最后工具和验证证据。
- 重启时检测 checkpoint 并在时间窗口内自动恢复。
- 限制重启频率以防止崩溃循环（窗口内最大 N 次重启）。
- 交互层（如飞书前端）作为持久守护进程运行；核心 CLI 仅用于交互使用。

## 浏览器自动化

- **DOM 蒸馏**：将 HTML 噪声过滤为高信噪比的语义描述。不要把原始 DOM 喂给 LLM。
- **SSO 状态复用**：复用已有浏览器配置文件，避免登录挑战。
- **原生设置器**：对输入字段使用原生 DOM setter + 事件链。点击前检查 `disabled`。
- **等待后重扫**：如果扫描返回空/不完整，等待后重新扫描。永远不要从第一次扫描就下结论。

## 委托模式

### 子 Agent（本地）
生成有界子会话，拥有独立工作目录、角色和超时。用于独立子任务。

### Swarm（并行）
为独立任务启动多个隔离子会话。默认最大并发数为 4。全部完成后聚合结果。

### 外部 CLI 委托
委托给另一个 LLM CLI（gemini、qwen、claude、codex）获取第二意见、并行调查或备份执行。默认异步启动。

## 工具安全

1. **不要无条件 kill python** — 可能杀死 agent 自身。使用精确 PID。
2. **不要用 `os.kill` 做存活检查** — 使用 `ps` 或进程检查。
3. **不可逆操作** — 先询问用户。
4. **受保护的写入** — 默认 dry-run；发送/发布/创建需要显式 `confirm=true`。
5. **编码安全** — 使用安全的文件读取工具，不要用原始 `cat`/`type`。

## 工作记忆（Checkpoint）

维护一个短期工作记事本，每轮自动注入以防止长任务中的信息丢失：

- 在早/中期调用，不要在结束时调用。
- 存储：用户需求、关键约束、陷阱、文件路径、进度、下一步。
- 不存储：临时信息、明显上下文、用户切换任务后的旧任务信息。
- 宁可过度更新也不要丢失关键信息。

## 反模式

- 不要在模糊的"继续"后继续扩展已完成的用户请求。
- 不要在用户已缩小范围后重新读取大型外部仓库。
- 不要让模型延迟导致前端静默失败；报告忙碌/状态。
- 不要为小型本地持久状态问题添加重依赖。
- 不要在用 `uname -a`、`pwd`、`command -v` 验证前断言命令缺失。
- 不要相信摘要；在详情页验证数字。
- 不要让已完成工作只存在于聊天记录中 — 归档它。
