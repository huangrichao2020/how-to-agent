# 抖音内容提取实战方法论

## 核心结论
**不要尝试在服务器上直接通过 HTTP 请求或简单的 Headless 浏览器抓取抖音内容。** 抖音拥有国内最强的风控体系，服务端 UA 检测、强制登录弹窗、图形验证码（滑块/拼图）以及跨域 iframe 保护使得自动化提取极其困难且不稳定。

## 已验证的失败路径 (避坑指南)
1. **HTTP 请求短链接 (`v.douyin.com`)**：❌ 服务端检测 UA，非真实浏览器环境直接 302 重定向至首页。
2. **移动端页面 (`m.douyin.com`)**：❌ 同样会重定向至桌面版并触发强制登录。
3. **搜索接口**：❌ 极易触发图形验证码，导致 IP 被临时封锁。
4. **外部 API (TikHub 等)**：⚠️ 需要付费或注册获取 API Key，且有额度限制。
5. **GitHub 开源库 (TikTokDownloader 等)**：❌ 均依赖有效的 Cookie 和复杂的签名算法（X-Bogus/A-Bogus），维护成本极高。

## 唯一可行的自动化方案：AmazingData (本地中转)
如果用户拥有 **Windows 电脑** 并运行了 **AmazingData/通达信** 等行情软件，可以通过部署在本地的 `amazingdata` 服务进行中继。
- **原理**：Windows 端作为“人头”维持登录态和会话，Linux 服务器通过内网穿透或公网中继调用本地 API。
- **优势**：完全绕过风控，数据实时且稳定。
- **配置**：
  - 公网地址：`https://www.ai10088.com/amazingdata`
  - 认证：使用 `AMAZINGDATA_PUBLIC_RELAY_TOKEN`。
  - **注意**：必须确保 Windows 主机开机且相关进程正在运行，否则接口会返回 500 错误。

## 推荐的半自动化工作流 (无 Windows 环境)
1. **手机操作**：用户在手机抖音 APP 打开口令/链接。
2. **内容复制**：长按复制文章文字，或直接截图。
3. **AI 处理**：将文字或图片发给 AI 助手进行分析、总结或归档。

## 替代数据源 (新闻/快讯)
如果需要获取财经新闻而非特定抖音视频，优先使用以下稳定接口：
- **财联社电报**：`curl https://www.cls.cn/telegraph` + 正则提取 `content` 字段。
- **华尔街见闻**：`https://api-one-wscn.awtmt.com/apiv1/content/articles`。

## 经验教训
- **涉及时间的务必用代码确认**：日期推算容易出错（如星期几、节假日），必须使用 `datetime` 库动态获取。
- **不要硬刚风控**：当遇到强制登录或复杂验证码时，立即切换为“半自动化”或“本地中继”方案，节省调试时间。
