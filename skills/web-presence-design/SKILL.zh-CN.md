# 网页形象设计

用户要的是公开面对访客的网页时使用这个 skill：官网、产品首页、课程页、客户案例页、作品集、代理商/工作室网站、SaaS 落地页、发布页、营销专题页。

## 核心立场

做网页形象，不是套模板。

```text
品牌事实 -> 受众承诺 -> 信息架构 -> 视觉方向 -> 实现 -> 截图验收
```

不要从组件库开始。先判断这个页面要让访客相信什么、感受到什么、理解什么、采取什么行动。

## 和其他 skill 的分工

- `huashu-design`：HTML 原型、视觉探索、动效 Demo、幻灯片、高保真设计探索。
- 本 skill：生产级官网、课程页、客户案例页、营销页。
- `platform-writing`：文章、飞书文档、腾讯文档，不是网站。

## 工作流

1. **判断页面类型。**
   先选一个主类型：
   - 官网/产品官网；
   - 课程落地页；
   - 客户案例页；
   - 作品集/代理商网站；
   - SaaS/产品发布页。

2. **收集上下文和资产。**
   涉及具体品牌或产品时，先验证事实，再找真实资产：logo、产品截图/渲染图、课程封面、讲师照片、客户 logo、客户 quote、结果数据、界面截图、品牌色。核心资产缺失时，可以用诚实 placeholder，但要明确指出缺口。

3. **写页面承诺。**
   设计前先写清楚：
   - 受众是谁；
   - 一句话承诺；
   - 主要转化动作；
   - 信任证据；
   - 离开页面后希望记住什么。

4. **选择视觉方向。**
   只选一个明确方向并贯彻：
   - 高级 SaaS：冷静、精确、产品主导、证据强；
   - 编辑感：图片主导、字体有性格、叙事感强；
   - 课程教育：温暖、结构清楚、有学习进度感；
   - 客户案例：可信、具体、结果先行；
   - 创意工作室：构图更大胆，艺术指导更强。

5. **先结构，后打磨。**
   优先沿用项目已有技术栈和组件。新 React/Next 项目默认用 Next.js 或 React、Tailwind、shadcn/Radix 兼容组件，以及项目已有图标库。导入包前先检查 `package.json`。

6. **视觉验收。**
   跑起来，至少截桌面和移动端，检查 console、横向溢出和第一屏。若页面用于销售或教学，第一屏必须能看到品牌/产品信号和清楚下一步动作。

## 页面范式

选择官网、课程页、客户案例页的结构时，读 `references/page-patterns.md`。

判断该借鉴哪些外部 skill 或模板时，读 `references/source-map.md`。

## 反 AI 味规则

- 不默认紫蓝 AI 渐变 hero。
- 不把三个功能卡片当成整个页面。
- 依赖信任的页面不要编假数据、假评价、匿名客户 quote。
- 产品页第一屏必须有产品信号。
- 课程页必须有学习成果、讲师可信度、课程结构和证明。
- 客户案例页必须有前后对比、具体数字、客户背景和实施过程。
- 能用真实 logo、截图、产品图、客户素材时，不要用装饰图顶替。

## 输出约定

非平凡页面至少交代：

1. 页面类型和页面承诺；
2. 分区规划；
3. 实现改动；
4. 截图或预览路径；
5. 资产或事实缺失时剩下的打磨点。

如果这次工作形成可复用经验，要沉淀成记忆、技能、方法论和印象，而不只是交付代码。
