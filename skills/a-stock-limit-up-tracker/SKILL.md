# A股涨停板实时追踪与分类

## 一句话版本

自动化追踪 A 股涨停板，按板块分组并识别龙头/身位/跟风股。核心：MX API 获取数据 + reason 字段真实逻辑 + 梯队结构分类。龙头定方向，身位做套利，退潮期空仓。

## 如何使用本技能

1. **先运行决策树**: `checklists/decision-tree.md`
2. **从 philosophy 开始**: 确认核心逻辑和关键原则
3. **按需加载 references**: 匹配问题到数据解析或坑文档
4. **交付前运行**: `checklists/ship-readiness.md`

## 核心反模式（看到这些立刻停下）

- **"直接用行业分类汇报"** → reason 字段才是编辑部人工标注的真实逻辑，优先用 reason
- **"不剔除 ST 股"** → ST 股有独立行情，会误导主线判断
- **"配额耗尽还继续调用"** → 每日 20 次/Key，检查配额再调用
- **"概念字段直接按管道符分割"** → 含顿号会破坏分割，优先提取稳定字段
- **"非交易时段查实时涨停"** → 数据不更新，无意义

## 异常处理与容错机制

### API 调用异常
- **配额不足**：调用前检查剩余配额。若 `< 2`，切换到备用 Key 或返回上次缓存数据并标注时间。
- **超时/网络错误**：首次失败后等待 3 秒重试，最多重试 2 次。全部失败后返回 "API 不可达，返回缓存数据" 并附上缓存时间戳。
- **返回空数据**：若 API 返回 0 条涨停记录，先确认是否非交易时段。若为交易时段，标记 "数据异常" 并尝试备用数据源。
- **HTTP 429 (限流)**：立即停止调用，等待 60 秒后以最低频率（每 30 秒一次）重试。
- **HTTP 500/503 (服务端错误)**：等待 10 秒重试一次，仍失败则标记服务不可用。
- **返回格式变更**：若预期字段缺失（如 `reason` 字段不存在），降级使用 `plate` 字段作为替代，并在报告中注明 "reason 字段缺失，使用 plate 替代"。

### 数据解析异常
- **概念字段分割失败**：若 `concept` 字段包含顿号（`、`）或其他非常规分隔符，不直接 split。优先使用正则匹配已知概念库，或提取 `reason` 字段。
- **ST 股识别失败**：若股票名称不含 "ST" 但代码以 `60`/`00`/`30` 开头，额外检查涨跌幅是否异常（如连续多日 ±5%），标记为疑似 ST 股并人工复核。
- **数据脏乱**：若 API 返回的股票代码格式不规范（如带空格/前后缀），先清洗：去除空格、补齐前缀（沪市补 `SH`、深市补 `SZ`）。
- **重复数据**：同一股票出现多条记录时，取最新时间戳的记录，丢弃旧数据。

### 分类逻辑异常
- **无法确定龙头**：若某板块多只股票同时首板涨停且无明确领涨特征，标注 "无明确龙头，多股并列"，不强行排序。
- **梯队断档**：若某概念仅有首板无连板，标注 "无梯队深度，疑似一日游"。
- **概念归属模糊**：若一只股票同时属于多个概念且无法确定主线，在报告中列出所有归属概念，由人工判断。

### 推送/输出异常
- **推送渠道不可达**：若飞书/微信推送失败，保存到本地文件 `~/wiki/raw/limit-up-fallback-YYYYMMDD.md`，下次发送时追加补发。
- **输出内容截断**：若涨停数量过多（>50 只），按梯队优先级截断，输出 "前 N 只核心涨停股 + 其余 X 只略"。

### 交易时段判断
- **非交易时段误触发**：盘中数据在 15:00 后不再更新。非交易时段查询时，返回最近一个交易日的收盘数据并明确标注日期。
- **节假日/调休**：参考 A 股交易日历，节假日自动跳过。无法确定时，以 API 是否返回新数据为准。
- **午间休市**：11:30-13:00 数据静止，此时查询返回上午收盘状态并标注 "午间休市中"。

### 缓存与回退
- **缓存策略**：每次成功获取数据后缓存到 `~/wiki/cache/limit-up-latest.json`。API 不可达时自动降级到缓存。
- **缓存过期**：缓存超过 24 小时标记为过期，使用时必须标注 "数据已过期"。
- **全链路失败**：API + 缓存均不可用时，返回 "数据服务不可用，请检查网络或 API Key 状态"。
