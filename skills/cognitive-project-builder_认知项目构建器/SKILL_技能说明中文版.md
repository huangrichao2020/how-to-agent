# 认知项目构建器

当用户不是要泛泛查资料，而是要把自己的领域经验做成可长期调用的认知体系时，使用这个 skill。

核心前提：

```text
认知项目不是 AI 的知识整理，而是用户的经验体系化。
用户给经验密度，AI 给结构化能力。
```

完整方法读取：

```text
references/cognitive-project-methodology.zh-CN.md
```

## 工作流

1. 收集领域种子：领域名、关键词、关键概念、心得、看法、场景、误判、目标用途。
2. 提炼高能碎片：反复出现的词、痛点、冲突、失败模式、一句话洞察。
3. 稳定命名：把模糊感觉变成可复用术语。
4. 建立模型：状态机、阶段论、信号表、公式、红线、校验器。
5. 教练化：诊断顺序、证据读取、优点/风险、下一步动作、话术、复盘指标。
6. 案例化：把真实场景匿名成固定结构案例。
7. 项目化：落成 `README`、`SKILL`、`methodology`、`references`、`cases`。
8. 迭代：每个新场景都要确认、修正、拆分或新增模块。

## 输出结构

```text
领域种子：
关键词/关键概念：
高能心法：
核心模型：
教练流程：
案例清单：
项目结构：
下一步采样问题：
```

## 反模式

- 不要在用户没有真实种子时写百科。
- 不要把用户自己的锐利语言磨平。
- 不要停在感悟和金句，要继续做成模型、教练和案例。
- 不要把私人原始记录或可识别人物写进项目。
- 不要太早宣布体系完整，必须让案例持续校验模型。
