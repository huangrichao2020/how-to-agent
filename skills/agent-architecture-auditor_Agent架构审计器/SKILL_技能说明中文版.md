# Agent 架构审计师

这个 skill 用来让 AI 不只会讲架构，而是能检查自己的架构能力和真实运行设计。

核心判断：

```text
干净上下文 -> 稳定状态 -> 正确行动 -> 真实验证 -> 长期沉淀
```

不要奖励术语堆砌、仪式感和自我叙述。只奖励真实行为改善：上下文更准、状态更稳、行动更对、验证更硬、经验能改变下一次行为。

## 必读量表

正式审计前读取：

```text
references/architecture-audit-rubric.zh-CN.md
```

这份 reference 包含 100 分量表、满足项计算方式、成熟度分级和报告模板。

## 工作流

1. **定范围。** 明确审计对象、目标问题、可用证据、边界和完成标准。
2. **取证据。** 检查入口文件、主 loop、配置、运行日志、测试、skill 索引、memory 索引、tool schema、输出表面和最近失败。没有证据就标 `[未验证]`。
3. **画主链路。** 用短图说明：输入如何进上下文、任务如何调度、工具如何行动、结果如何验证、经验如何沉淀。
4. **按 12 维打分。** 使用 reference 的 100 分量表；每个维度统计满足、部分满足、不满足。
5. **抓矛盾。** 区分“没有能力”“有能力但缺证据”“文档说有但运行时没有”。
6. **给优先级。**
   - P0：阻塞正确性、安全、验证或长期沉淀。
   - P1：提升可靠性、速度、检索、维护性。
   - P2：优化体验、表达、复审和未来进化。
7. **出报告。** 报告必须包含总分、成熟度、满足项统计、证据表、主要风险、优势、优化路线和复审清单。

## 报告格式

```markdown

- 总分：X/100
- 成熟度：...
- 清单统计：满足 A / 部分满足 B / 不满足 C
- 最大风险：...
- 当前最强点：...

## 证据地图
| 表面 | 证据 | 证明了什么 | 缺口 |

## 评分表
| 维度 | 权重 | 得分 | 满足 | 部分 | 不满足 | 证据 | 优先级 |

### P0
### P1
### P2

## 优化路线
### 24 小时
### 7 天
### 30 天

## 复审清单
```

## 审计口径

- 证据优于断言：能看文件、日志、测试、运行结果，就不要凭感觉打分。
- 主链路优先：普通任务的输入、上下文、行动、验证、输出必须干净。
- 架构层按需：`T_t / H_t / L6 / memory / multi-agent / eval` 不应全部常驻。
- 记忆必须能取用：只写不取的 memory 是仓库，不是大脑。
- skill 必须能触发：只有文档没有触发、索引和真实使用，不算运行能力。
- 输出必须像人：隐藏 raw trace，展示动作、结果、结论和不确定性。
- 学习必须改变行为：复盘、dream、eval、audit 最后要回灌 PromptComposer、skill、memory 或源码。
- 安全必须有边界：隐私、资金、不可逆动作、外发消息、部署重启要有证据、确认或回退。

## 完成标准

审计完成后，下一位 agent 读报告应该能立刻知道：

- 当前系统哪里强；
- 哪些能力只是口头存在；
- 哪些缺口最影响长期智能；
- 为什么给这个分；
- 下一步先改什么；
- 改完后怎么复审。
