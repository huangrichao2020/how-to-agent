# 横纵深度研究框架 (Horizontal-Vertical Analysis)

Adapted from the horizontal-vertical research pattern in `KKKKhazix/khazix-skills`, with Hermes defaults: 当前证据优先，一手来源优先，默认 Markdown 输出。

## 何时使用

- 用户要求"研究一下"、"竞品分析"、"摸清楚 XXX"、"深度调研"
- 需要全面了解某个产品/公司/技术/项目的历史和现状
- 需要对比多个竞品或替代方案
- 需要做出技术选型或市场判断

## 输出结构

1. **研究对象与范围** — 明确研究对象、时间范围、分析深度
2. **纵向分析 (Vertical)** — 起源、时间线、转折点、路径依赖
3. **横向分析 (Horizontal)** — 竞品、替代方案、用户群体、生态位
4. **交叉综合 (Cross-axis)** — 历史如何解释现状、替代方案揭示什么、可能未来
5. **证据附录** — 来源、缺口、不确定性

## 工作流

1. **明确范围** — 仅当研究对象或期望深度不明确时才确认
2. **收集当前证据** — 优先官方文档、GitHub releases/issues、一手声明、论文、 filings
3. **构建纵向轴** — 因果驱动，不是简单日期列表。每个节点说明"为什么发生"
4. **构建横向轴** — 从用户需求、工作流契合度、技术路线、采用率、社区健康度、运营摩擦度等维度对比
5. **交叉综合** — 明确给出"应借鉴什么、应适配什么、应避免什么、应持续观察什么"

## 风格规范

- 事实与判断严格分开
- 使用具体日期和证据，避免模糊表述
- 杜绝咨询行业套话（"赋能"、"生态协同"等）
- 除非用户要求，否则不生成 PDF
- 不确定性要明确标注，不要伪装确定性

## 错误处理与异常恢复

### 数据收集异常
| 情况 | 处理方式 |
|------|----------|
| 一手来源不可用（官网 404、项目已归档） | 使用 Wayback Machine 或 GitHub API 获取历史快照，标注数据来源和时间 |
| 信息矛盾（不同来源说法不一） | 列出矛盾点，注明各来源，不做无根据的判断 |
| 研究对象无公开信息 | 说明信息缺口，基于已知相似案例做类比分析 |
| 竞品信息不完整 | 标注缺失维度，用已有数据做部分对比 |
| 最新数据不可得（如财务数据延迟） | 标注数据截止日期，使用最新可用数据 |

### 分析质量保障
| 情况 | 处理方式 |
|------|----------|
| 纵向时间线信息断层 | 标注"信息缺口"，不强行填补；用推断替代时明确标注"推测" |
| 横向对比维度不统一 | 统一对比维度；无法统一的单独说明 |
| 样本量不足（竞品太少） | 扩大到相邻品类或替代方案 |
| 研究对象的领域不熟悉 | 先做领域背景扫描，再进入具体分析 |

### 常见陷阱与规避
| 陷阱 | 表现 | 规避方法 |
|------|------|----------|
| 幸存者偏差 | 只分析成功的竞品 | 主动纳入失败案例，分析失败原因 |
| 确认偏误 | 只找支持预设观点的证据 | 主动寻找反面证据 |
| 过时信息 | 引用多年前的数据或评论 | 标注每条信息的日期，优先近 1 年数据 |
| 信息过载 | 罗列大量信息缺乏重点 | 按重要性排序，前 3 个维度深入，其余简述 |
