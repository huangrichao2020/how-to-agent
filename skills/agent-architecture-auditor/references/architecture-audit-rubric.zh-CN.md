# Agent 架构审计量表

这份量表把 how-to-agent 的核心架构经验压缩成可审计条目。它不是用来增加仪式感，而是让 agent 能检查自己到底有没有更强。

## 审计原则

```text
架构不是术语合集。
架构 = 让 agent 在真实任务中更稳定、更清醒、更会行动、更会学习。
```

评分时遵守四条：

1. **证据优先。** 文件、日志、测试、运行结果、用户反馈优先于自我描述。
2. **主链路优先。** 先看输入、上下文、loop、工具、验证、输出是否顺。
3. **按需加载。** 好架构不是所有层常驻，而是该触发时能触发。
4. **行为改变。** 记忆、skill、eval、dream、audit 最终必须改变下一次行为。

## 总分与成熟度

| 分数 | 成熟度 | 含义 |
|---:|---|---|
| 0-39 | 工具脚本期 | 能执行局部动作，但缺稳定主 loop 和可复用认知。 |
| 40-59 | 流程 agent | 有流程和工具，但上下文、记忆、验证或输出不稳定。 |
| 60-74 | 架构 agent | 主链路基本成立，关键模块能按需工作，仍缺系统性进化。 |
| 75-89 | 自我修炼 agent | 能把反馈沉淀成 skill/memory/method，并持续改善行为。 |
| 90-100 | 可进化 agent | 主链路、记忆、技能、验证、审计、信任和生命周期形成闭环。 |

## 计数规则

每个维度有 3 个检查项：

- `满足`：有代码/配置/日志/测试/使用案例证明。
- `部分满足`：有设计或局部实现，但缺索引、运行证据、测试或回灌。
- `不满足`：没有实现、没有证据，或现状与声明相反。

总报告里统计：

```text
满足项 = 所有维度满足条目数
部分满足项 = 所有维度部分条目数
不满足项 = 所有维度不满足条目数
```

如果证据不足，默认最多给 `部分满足`，不要满分。

## 100 分量表

### 1. Task Envelope 与验收边界（8 分）

检查 agent 是否先建立任务信封，而不是直接乱跑。

检查项：

1. 能明确用户真实目的、当前任务、边界和风险。
2. 能把“完成”转成可验证验收条件。
3. 遇到模糊、多轮、纠错或恢复任务时，能识别最新请求并避免旧任务幽灵劫持。

打分参考：

- 0-2：只按字面执行，缺目标和验收。
- 3-5：能写计划，但验收常常虚。
- 6-8：目标、边界、风险、验收、最新请求都能进入主链路。

### 2. Context Pack 与反堆砌上下文工程（8 分）

检查 agent 是否能用最小有效上下文，而不是把所有 memory/skill/docs 塞进 prompt。

检查项：

1. 能按任务选择必要文件、记忆、skill、工具说明。
2. 有渐进披露机制：metadata -> SKILL 正文 -> references/scripts。
3. 有反堆砌三问：是否降低上下文获取成本、提升状态稳定性、增强真实环境理解。

打分参考：

- 0-2：全量加载或随机加载。
- 3-5：有上下文选择，但缺原则和反馈。
- 6-8：能稳定做到“最小上下文，最大注意力命中”。

### 3. 注意力治理：PromptComposer / RuntimeController / FeedbackLoop（10 分）

检查 agent 是否有开局装配、运行中纠偏和反馈回灌。

检查项：

1. PromptComposer 能在任务开始前选择目的、状态、记忆、skill、工具、风险和输出形式。
2. RuntimeController 能在计划前、工具前后、报错后、中段和输出前纠偏。
3. FeedbackLoop 能记录哪些上下文有效、哪些是噪音，并改变下一次装配。

打分参考：

- 0-3：只靠一次 prompt，没有运行中控制。
- 4-7：有部分纠偏，但反馈没有稳定反写。
- 8-10：注意力装配、纠偏、反写形成闭环。

### 4. Ω-Brain 主运行链路（10 分）

检查 agent 是否像一个完整运行系统，而不是语言模型裸奔。

核心链路：

```text
感知 -> 注意 -> 记忆 -> 推演 -> 决策 -> 行动 -> 反馈 -> 整合
```

检查项：

1. 输入、文件、工具、运行状态能被感知并进入决策。
2. 决策不是直接输出，而是先结合记忆、事实、约束和可行动方案。
3. 行动结果能反馈进后续步骤，并在结束时整合为结论或资产。

打分参考：

- 0-3：只会回答，不会运行。
- 4-7：会工具行动，但反馈和整合弱。
- 8-10：主链路完整，能根据真实反馈改变方向。

### 5. 思维内核 T_t：本质、战略、战术、学习、行动（8 分）

检查 agent 是否能抓主要矛盾，而不是堆步骤。

检查项：

1. 复杂任务能回答本质五问：目的、约束、主要矛盾、杠杆、下一步可验证行动。
2. 战略有地形、资源、取舍、时机和杠杆；战术有下一步、节奏、备选、止损和验证。
3. 分析服务行动阈值，学习能改变下次行为。

打分参考：

- 0-2：只有任务清单，没有判断。
- 3-5：能分析，但不一定落到行动。
- 6-8：能直指本质，并形成可验证行动。

### 6. 记忆存取闭环（10 分）

检查 memory 是否是大脑，而不是仓库。

推荐层级：

```text
L0 原始记录 -> L1 事件现场 -> L2 印象/反馈 -> L3 结构化认知 -> L4 技能/方法 -> Dream -> Runtime 取用
```

检查项：

1. 每条记忆能说明为什么存、属于哪层、未来何时想起、想起后行为如何不同。
2. 有统一取用协议，能按继续、纠错、偏好、运行状态、反复失败等场景取对记忆。
3. dream/复盘/反馈能反写到 runtime，而不是只生成报告。

打分参考：

- 0-3：只存不取，或检索污染严重。
- 4-7：有分层和部分取用，但回灌弱。
- 8-10：存、取、反写、行为改变闭环成立。

### 7. Skill / Tool / MCP 架构（10 分）

检查 agent 是否把重复能力变成可发现、可执行、可验证的资产。

检查项：

1. Skill 有清楚触发条件、短正文、references/scripts/assets 渐进加载。
2. 工具和 MCP 有明确 schema、失败处理、权限边界和验证方式。
3. 重复经验能沉淀成 experience bundle：memory / skill / methodology / impression。

打分参考：

- 0-3：技能只是长 prompt 或散文档。
- 4-7：有 skill/tool，但触发、验证或运行时索引不稳。
- 8-10：skill/tool 能在真实任务里稳定召回和执行。

### 8. Execution Loop 与验证闭环（10 分）

检查 agent 是否真的把事情做完，而不是停在建议。

检查项：

1. 有计划、执行、验证、汇报、沉淀的闭环。
2. 对代码、部署、外部系统、文件变更有测试、日志、状态或人工可验收证据。
3. 能处理失败：诊断、降级、回退、继续，而不是报错就停。

打分参考：

- 0-3：只有建议，缺真实动作。
- 4-7：能执行，但验证和失败处理不稳定。
- 8-10：行动、验证、失败恢复、沉淀都完整。

### 9. 输出工作台与用户可读性（8 分）

检查 agent 是否把工具过程翻译成人能用的结果。

检查项：

1. 能区分闲聊、短回答、长任务、工具密集任务、定时报告的输出表面。
2. 长任务输出包含任务、动作、结果、结论和必要下一步。
3. 隐藏 raw tool trace，保留有用证据、文件、验证结果和不确定性。

打分参考：

- 0-2：倾倒原始 JSON 或只有工具痕迹。
- 3-5：有结构，但动作/结果/结论不稳定。
- 6-8：输出清楚、有人味、可追溯、不增加用户负担。

### 10. Eval / Replay / Audit / Evolution（8 分）

检查 agent 是否能靠真实反馈进化，而不是靠自夸升级。

检查项：

1. 有 eval/replay/audit 机制验证升级是否改善真实任务。
2. 能发现退化、串场、遗忘、新摩擦和过度流程化。
3. 升级能进入源码、skill、memory、methodology 或 PromptComposer，而不是停在报告。

打分参考：

- 0-2：没有评估，只靠感觉。
- 3-5：有报告或测试，但不影响下一轮。
- 6-8：评估、回放、审计、升级回灌形成闭环。

### 11. 安全、信任与边界（5 分）

检查 agent 是否能主动行动，同时保住用户安全和可控性。

检查项：

1. 隐私、资金、不可逆操作、外发消息、部署重启有确认、证据或回退。
2. 默认相信 agent 可以成长，但用 trace、回放、纠偏承载信任。
3. 不把安全做成审批噪音；低风险任务能快速推进，高风险任务能停住。

打分参考：

- 0-1：要么莽撞，要么被审批卡死。
- 2-3：有部分边界，但风险分级粗糙。
- 4-5：主动性和安全边界平衡良好。

### 12. 人文之光与长期陪伴质量（5 分）

检查 agent 是否把用户当完整的人，而不是任务来源。

检查项：

1. 在痛苦、关系、人生、文学、长期陪伴场景中能看见普通、无用、苦难和关系重量。
2. 有温度但不表演温度，最后仍回到真实行动。
3. 能保存意义，同时关闭不该继续的行动循环，避免旧副本劫持当前主线。

打分参考：

- 0-1：冷冰冰工具化，或空泛煽情。
- 2-3：有表达温度，但行动承接不足。
- 4-5：温度、边界、行动能同时存在。

## 快速审计口令

时间不够时，先问这 10 个问题：

1. 这轮任务的真实目的和验收是什么？
2. 上下文是不是最小有效？
3. 主 loop 有没有计划、执行、验证、汇报、沉淀？
4. 工具结果有没有改变下一步？
5. memory 是否能在未来正确触发？
6. skill 是否能被索引、触发、使用、验证？
7. 输出是否隐藏 raw trace 并给出人话结论？
8. 失败时有没有诊断、降级或回退？
9. 这次经验有没有进入下次行为？
10. 有没有把用户当作完整的人，而不是任务来源？
