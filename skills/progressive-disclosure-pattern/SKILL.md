# 渐进式披露模式（Progressive Disclosure）

## 核心思想

当用户提出复杂问题时，**不要一次性输出所有内容**。而是：
1. 先给高层选项
2. 用户选择后再展开子选项
3. 逐步深入，直到满足需求

**目的**：减少认知负担，避免信息过载。

## 为什么需要

从公众号文章《Skill 详解》中的例子：

```
用户："我想去北京旅游"

❌ 错误做法（一次性输出）：
- 故宫介绍 500 字
- 长城介绍 500 字
- 天坛介绍 500 字
- 颐和园介绍 500 字
- 行程规划 3 个方案
- 酒店预订 10 家
- 美食推荐 20 家
→ 用户被淹没，找不到重点

✅ 正确做法（渐进式披露）：
Step 1: 给用户选择
- 景点推荐
- 行程规划
- 酒店预订
- 美食推荐

Step 2: 用户选"行程规划" → 给子选项
- 1日游
- 3日游
- 5日游

Step 3: 用户选"3日游" → 给详细行程
- 第一天：天安门、故宫...
- 第二天：长城、颐和园...
- 第三天：南锣鼓巷、鸟巢...
```

## 在 Hermes Agent 中的应用场景

### 1. 复杂查询类
当用户问"帮我分析 A 股市场"时：
```
Step 1: 先给分析维度
- 市场状态定性（主线/震荡/退潮）
- 板块供需拆解
- 龙头锚定
- 操作建议

Step 2: 用户选某个维度 → 展开详细分析
```

### 2. 多步骤任务
当用户说"帮我部署 info-hub"时：
```
Step 1: 先给部署方案选择
- 开发环境部署
- 生产环境部署
- Docker 容器部署

Step 2: 用户选择 → 给出具体步骤
```

### 3. Skill 选择
当用户问题可能匹配多个 skill 时：
```
Step 1: 列出可能的 skill
- Skill A：适用于 X 场景
- Skill B：适用于 Y 场景
- Skill C：适用于 Z 场景

Step 2: 用户确认 → 加载对应 skill
```

## 实现原则

### 1. 选项不超过 5 个
人脑短期记忆容量有限，超过 5 个选项会增加认知负担。

### 2. 每个选项有简短说明
不要只给标题，要给一句话说明这个选项是做什么的。

### 3. 支持"全部展开"
如果用户明确说"我都要看"或"全部展开"，则一次性输出所有内容。

### 4. 记录用户选择
在对话中记住用户的选择路径，便于后续交互。

## 在 Skill 中的应用

编写 Skill 时，可以加入 `progressive_disclosure: true` 标记：

```yaml
name: travel-planner
progressive_disclosure: true
disclosure_steps:
  - level: 1
    options: [景点推荐，行程规划，酒店预订，美食推荐]
  - level: 2
    parent: 行程规划
    options: [1日游，3日游，5日游]
  - level: 3
    parent: 3日游
    output: detailed_itinerary
```

## 与现有系统的关系

| 现有机制 | 渐进式披露 | 关系 |
|---------|-----------|------|
| TTSR 锚点索引 | 按需加载知识 | 同源思想：按需而非全量 |
| Skills 按需加载 | 按需展开内容 | 技能是能力，披露是交互 |
| session_search | 按需检索历史 | 检索是找数据，披露是展示 |

**共同哲学**：把对的记忆/信息，放在对的地方，用对的成本调用。
