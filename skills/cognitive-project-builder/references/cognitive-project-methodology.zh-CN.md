# 认知项目构建方法论

## 一句话

认知项目不是从通用理论开始，而是从用户自己的关键词、关键概念、真实心得、看法和场景开始，通过 AI 的提纯、命名、建模、教练化、案例化和项目化，演化成可长期调用的领域认知系统。

```text
用户给经验密度，AI 给结构化能力。
用户给真实场景，AI 给模型、教练和 skill。
```

## 用户必须提供的种子

```text
领域名称：这个项目研究什么？
关键词：用户常说的词、黑话、术语、口头禅。
关键概念：用户已经隐约形成的判断框架。
实际心得：真实经历后得到的经验。
看法与偏见：用户相信什么、怀疑什么、讨厌什么。
真实场景：具体发生过什么。
常见误判：过去哪里看错、做错、过度反应。
目标用途：以后要让这个项目怎么帮自己判断和行动？
```

没有这些种子时，先提问采样，不要直接写“大而全”体系。

## AI 的五个职责

```text
提纯：从用户碎片里找高能概念。
命名：把模糊感觉变成稳定术语。
建模：把心得变成结构、状态机和判断表。
教练化：把理论变成可诊断、可指引、可复盘的流程。
项目化：把内容沉淀成 README / SKILL / references / cases。
```

AI 不是替用户凭空发明一个领域，而是把用户的经验体系化。

## 六层沉淀法

### 1. 原始材料层

收集真实材料，而不是先写理论。

```text
我遇到了什么？
我反复卡在哪里？
我有哪些痛感、遗憾、冲动、误判？
我有哪些一句话洞察？
我有哪些具体场景？
```

认知项目的原料不是资料，而是高压经验。

### 2. 心法层

把复杂经验压成能背下来的短句。

好心法的标准：

```text
短。
狠。
能执行。
能在情绪上头或现场压力下救人。
```

### 3. 模型层

把心法扩成判断系统。

```text
状态机：现在处于什么状态？
阶段论：事情发展到哪一步？
信号表：对方/环境给了什么信号？
公式：核心变量是什么？
红线：什么绝对不能做？
校验器：出口前问哪几个问题？
```

### 4. 教练层

把模型变成稳定输出流程。

```text
现在是什么局？
有哪些证据？
我哪里做对了？
我哪里错了？
下一步 24 小时怎么做？
7 天怎么做？
长期怎么调整？
我可以直接说什么/做什么？
如何复盘？
```

### 5. 案例层

每个真实场景都要匿名化并写成训练样本。

```text
场景
容易误判
更准确的判断
正确动作
不该做
教练判断
一句原则
```

没有案例的模型容易空；没有模型的案例只是故事。

### 6. Skill 层

把项目封装成可被 agent 调用的结构。

```text
project/
├── README.md
├── SKILL.md
├── SKILL.zh-CN.md
├── methodology/
│   └── index.zh-CN.md
├── references/
│   └── module-name.zh-CN.md
└── cases/
    └── case-01-topic.zh-CN.md
```

触发词必须来自用户自己的语言。用户以后说出这些词，skill 才能自然回到正确模块。

## 标准演化流程

```text
用户输入领域种子
-> AI 提炼关键词和概念
-> 共同确认核心心法
-> AI 建立模型和分层
-> 用户继续提供真实案例
-> AI 抽象成 case
-> AI 生成教练流程
-> AI 封装成项目
-> 后续持续追加新场景
```

## 质量检查

```text
是否保留了用户自己的关键词？
是否有能背下来的心法？
是否有状态/阶段/信号/公式/红线之一？
是否能像教练一样分析真实场景？
是否至少有一个匿名 case？
是否避免泄露隐私和原始记录？
是否能被 skill description 触发？
```

## 一句总纲

```text
不要从理论开始，要从真实痛点开始；
不要停在感悟，要压成心法；
不要停在心法，要建成模型；
不要停在模型，要做成教练；
不要停在教练，要沉淀案例；
不要停在案例，要封装成可反复调用的 skill。
```
