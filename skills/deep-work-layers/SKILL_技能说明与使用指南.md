# 深度做事框架（L0-L5 分层）

## 触发条件

- 接到复杂任务，需要确定处理深度
- 交易决策前，需要识别自己在哪一层
- 用户沟通出现信息断裂（不理解对方意图）
- 复盘时分析今天的决策质量

## 认知层级识别

| 层级 | 名称 | 信号 | 正确做法 |
|------|------|------|---------|
| L0 | 本能层 | "报错了快帮我改"、跌了就跑 | 暂停，先识别问题 |
| L1 | 情绪层 | "我觉得不对劲"、害怕错过 | 列出客观指标，排除情绪 |
| L2 | 事件层 | "把这个功能加了"、看个股涨跌 | 可以执行，但先问 L5 意图 |
| L3 | 模式层 | "用 XX 模式做"、龙头战法 | 好，确认 L4 约束 |
| L4 | 结构层 | "考虑一下依赖关系"、供需分析 | 很好，确认 L5 意图 |
| L5 | 规则层 | "本质上是..."、人性/执念 | 直接翻译为 L2 动作 |

## 做事流程（四层漏斗）

```
L5 意图层 → 为什么要做？（减少自由度/增加控制）
  ↓
L4 约束层 → 环境限制是什么？（内存、网络、时间、资金、制度）
  ↓
L3 方法层 → 用什么方法？（已有 skill/methodology/工作流）
  ↓
L2 执行层 → 具体步骤？（调查 → 规划 → 执行 → 留痕）
```

**L0/L1 不是做事层，是干扰层。识别到就跳过。**

## 交易映射

- **L5**：人性/执念/住相/供需 → 预判市场自由度重分配
- **L4**：市场制度、涨跌停、T+1、北向资金规则 → 理解约束
- **L3**：龙头战法、板块轮动、资金流向模式 → 识别规律
- **L2**：个股买卖点、仓位、止损 → 具体执行

## 跨层翻译

- **用户说"直接改"** → L5 意图层，跳过 L3/L2 解释，直接执行
- **用户问"为什么"** → L3/L4 模式层，给结构解释
- **用户给具体报错** → L2 事件层，给具体修复方案
- **禁止跨层输出**：L2 问题不倒 L5 哲学课，L5 意图不列 L2 清单

## 原生集成架构（已落地）

L0-L5 框架不是 Skill，而是**系统本能**。它通过以下 5 层注入到每次对话中：

1. **身份层 (SOUL.md)**: `~/.hermes/SOUL.md` — System Prompt 第一块，默认以 L3+ 运作
2. **注入层 (config.yaml)**: `agent.system_prompt` — 每次 API 调用叠加注入精简规则
3. **启动层 (BOOT.md)**: Gateway 重启时加载完整框架与交易映射
4. **记忆层 (Memory)**: 行为规则摘要，每 turn 注入
5. **参考层 (gbrain/skill)**: `deep-work-framework` (方法论) + `deep-work-layers` (触发式工具)

**核心心法**：不是听不懂，是根本无法被解析。先对齐层级，再对齐内容。
## 每日自检

1. 我今天在哪一层做事最多？
2. 我有没有被 L0/L1 劫持？
3. 我今天有没有做一次 L5 → L2 的翻译？

## 关键心法

- "如果所有人都在同一层，系统将无法分工" — 分层是常态，不是异常
- "不是听不懂，而是根本无法被解析" — 信息断裂是跨层的正常现象
- 先对齐层级，再对齐内容
