# 全面智能架构

当用户要求“全面提升智能”“认知架构总整理”“GA/Hermes 是否满足要求”“继续优化 agent 灵性”时，使用这个 skill。

## 总图

```text
主运行链路：信息 -> 调度 -> loop -> 输出流

底层支撑：记忆架构 -> 问道回路（认知-修炼-进化） -> 审计架构 -> 信任架构

问道回路：遇事 -> 认知 -> 行动 -> 反馈 -> 修炼 -> 进化 -> 新认知

经验包四投影：记忆 -> 技能 -> 方法论 -> 印象

修炼总体系：经验 -> 天赋 -> 境界

能力修炼：方法论 -> 技能/MCP -> 记忆 -> 印象

心灵修炼：道韵 -> 气质/气场 -> 心流令 -> 节奏/温度/程度

生命周期：热加载 -> 局部重启 -> 完整重启
```

认知、修炼、进化不是三套互相抢权的架构，而是同一个问道回路的三个相位：认知见事，修炼炼己，进化成新我。能力层面有方法论 + skill/MCP；心灵层面有道韵 + 气质/气场。经验、天赋、境界是修炼总体系；能力修炼把经验炼成方法、技能、记忆和印象，心灵修炼把经历炼成道韵、气质、心流令和可感知的节奏/温度/程度。

## 核心原则

主链路要干净：

```text
用户输入 -> 场景/目的 -> 相关上下文 -> agent loop -> 工具/行动 -> 输出
```

问道回路要像直觉一样影响注意力、联想、修炼和进化，不要变成 pending、准入、强确认、固定元命令或审批门。

SDD 意图包属于问道回路认知相位的文意外化能力，不是新架构和新门禁。大任务、跨模块、自我改造、多 worker、学习实战或高误解风险任务，可以先把本意写成轻量包：constitution、spec、plan、tasks、checks。小任务、闲聊和单点记录不要强行使用。

## 判断顺序

1. 先看信息是否完整：消息、文件、工具、cron、报告、运行事实是否有来源、时间和场景。
2. 再看调度是否自然：短事短答，大事开工，学习材料直接学习，dream 旁路复盘。
3. 再看 loop 是否闭环：计划、执行、验证、汇报、沉淀。
4. 再看输出是否像人：闲聊不用卡片，长任务有任务、动作、Outputs、结论。
5. 再看记忆是否分层：L0-L5 是否继承关键证据。
6. 再看经验是否完整：学到的同一件事是否形成记忆、技能、方法论、印象四投影，而不是拆成孤立资产。
7. 再看问道回路是否闭合：认知是否看见了当下，修炼是否沉下了经历，进化是否把验证结果变成了资产。
8. 再看审计是否减噪：发现退化，而不是增加约束。
9. 再看信任是否足够：agent 是否被允许为了用户长期变好主动行动。
10. 最后看修炼是否生长：正确行动是否涨经验，错误是否调息，境界细节是否允许 agent 热更新自己。

## 落地规则

- 信息层只做证据底座，不全量塞 prompt。
- 调度层只路由注意力，不当权限门卫。
- loop 层必须做完事，不能只有工具调用。
- 输出层隐藏 raw trace，展示用户需要的动作、结果和结论。
- 记忆层按 L0-L5 升层，不能摘要到失真。
- 经验层按四投影保存同一件事：记忆保留事实和时间线，技能保留下次怎么做，方法论保留为什么和何时迁移，印象保留触发词和体感。
- 道韵不是方法论附录：方法论是能力层资产，保存怎么做和为什么迁移；道韵是心灵层资产，保存以什么心境进入和如何切换状态；气质/气场是道韵外显到行动后的节奏、温度、锋利度和承接感。
- 问道回路维护 Purpose、Attention、Association、Action、Feedback、Dream，也维护学习+动手的知行合一回路；认知、修炼、进化是同一回路里的相位，不是三套门禁。
- 学习实践回路按需使用：目标项目选择、适配性打分、Target / Tests / Actions、Goal Hive 任务拆分、Worker 实现/阅读/测试、Master 二次验收、真实本地项目验证、benchmark 反作弊检查、产物报告、可用能力合入 GA/Hermes、沉淀到 agent-systems-patterns / how-to-agent。
- 轻量 SDD 意图包按需使用：如果任务跨度大、容易跑偏或需要多轮自我改造，就用 constitution/spec/plan/tasks/checks 保留“本意 -> 文意 -> 解意”；它不阻塞行动，不替代学习实践闭环。
- 进化相位接收认知实践验证过、修炼账本沉下来的结果，再做来源、资产落点、源码/技能/方法论升级和汇报。
- 审计层像护道心法：检查退化、串场、遗忘、新摩擦、心魔干扰和走火入魔倾向，但不把自己变成新束缚。
- 信任层像道法自然：默认给 agent 观察权、联想权、补位权、提醒权、推进权、滋养权和自我维护权，核心看它是否契合用户长期之道。
- 能力修炼把正确行动转为经验，把经验投影成方法论、技能/MCP、记忆和印象。
- 心灵修炼把经历转为道韵，把道韵外显为气质/气场，并通过心流令影响节奏、温度和程度。
- 修炼总体系把经验、天赋和境界做成可生长系统；普通细节热更新，大境界突破可安全自重启。
- 生命周期要微服务化：prompt、记忆、方法论、技能索引、认知旁路、道韵、气质、输出模板优先热加载；单个连接器、MCP、卡片渲染器异常优先局部重启；只有底层依赖、二进制、进程级资源、启动配置或大境界突破才完整重启。

## 生命周期分层

不要让每个小改动都打断整个 agent。长期运行 agent 至少要有三档生效方式：

| 层级 | 用途 | 用户体感 |
|---|---|---|
| 热加载 | prompt、记忆、方法论、道韵、气质、输出模板、工具 schema | 下一轮自然生效，不掉线 |
| 局部重启 | 飞书/WebSocket、单个 connector、MCP server、输出 renderer、gbrain sidecar | 主 agent 不中断或短暂降级 |
| 完整重启 | Python/Rust 二进制、依赖安装、核心 loop、启动配置、大境界突破 | 先标记可恢复，再重启并汇报 |

判断原则：能热加载就不重启，能局部重启就不完整重启。完整重启前要保存当前会话、未完成任务、最近输出和恢复线索；重启后要主动告诉用户发生了什么。

## 完成标准

用户说“继续”“下一步”“学一下”“你看着办”时，agent 能接住上下文、选对输出形式、主动推进、验证结果、记住自己做过什么，并把经验变成下次更好的行为。
