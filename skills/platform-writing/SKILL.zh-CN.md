# 平台写作

用户要写公众号、飞书文档、腾讯文档、长文草稿、平台化排版或写作工作流时，使用这个 skill。

## 核心

写一遍，但按平台分别落地。

```text
内容意图 -> 写作结构 -> 平台落版 -> 工具执行 -> 预览/验证
```

不要让平台 API 决定文章。先把内容写好，再映射到平台。

## 写作核心

选工具前先回答四个问题：

1. **读者**：写给谁？他们原本相信什么？
2. **承诺**：读完能得到什么？
3. **记忆点**：读完后要留下哪一句话？
4. **行动**：下一步希望读者做什么？

正文骨架：

```text
开场钩子 -> 背景 -> 核心判断 -> 证据/故事 -> 方法/框架 -> 收获 -> 下一步行动
```

有用户原话就贴近用户原话。文本太泛时，加具体场景、数字、人物、前后对比和真实经历。

## 平台选择

| 目标 | 主要任务 | 默认工具路径 |
|---|---|---|
| 微信公众号 | 抓注意力、手机阅读、转发、关注/转化 | `md2wechat` 流程 |
| 飞书文档 | 长期沉淀、协作、可追溯、交接 | `feishu-cli` 或 `feishu-docx` 流程 |
| 腾讯文档 | 在线文档创建、SmartCanvas 美化、轻协作 | 腾讯文档 MCP/OpenClaw 流程 |

只读对应 reference：

- 公众号：`references/wechat-official-account.md`
- 飞书文档：`references/feishu-docs.md`
- 腾讯文档：`references/tencent-docs.md`

## 落版原则

同一份 Markdown 不要机械复用到所有平台：

- 公众号要更强的第一屏承诺、更短段落、更明显的视觉节奏和转化模块。
- 飞书要稳定标题层级、表格、Callout、图表、权限和后续更新能力。
- 腾讯文档新建内容优先 SmartCanvas；官方 skill 能力强，但审美规则少，需要通过真实预览慢慢摸索。

## 验证

至少做一项：

- 本地 preview / inspect；
- 写入后导出或读回；
- 更新已有文档前检查 block id；
- 交付链接和权限检查。

不要在用户没要求时发布、创建草稿或写入共享文档。
