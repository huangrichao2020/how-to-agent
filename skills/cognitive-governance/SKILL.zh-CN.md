# 认知治理

[English](SKILL.md) · [简体中文](SKILL.zh-CN.md)

当一个 agent 系统需要判断什么该记、什么该信、什么该抽象、什么该变成可重复行为时，使用这个 skill。

这不是存储模式，而是认知质量模式。

在 GA 或 Hermes 这类运行时里，它必须全局生效，而不是只在用户写日记时生效。每一次频道对话都应经过 Purpose 识别、注意力门控、上下文组装、回答/行动、反馈捕获和准入。日记只是输入面之一，和飞书消息、当天群聊、飞书文档、任务日志、工具输出、重启事件、笔记、用户真实生活记录并列。

使用原则：**写一遍，多路由**。用户写在飞书文档里，就读取文档；用户说“刚刚讨论的所有内容”，就使用近期会话证据；材料讲运行方式，就路由到 skill/SOP；材料讲真实生活，就路由到 L5；材料讲关系质量，就路由到滋养层。

## 核心原则

原始事件入记忆，验证断言入事实，可迁移解释入知识，可重复动作入技能，长期价值入身份。

在面向长期用户关系的 agent 中，还要加一句：能让用户更清楚、更有能量、更会判断、更能行动的互动，才进入滋养层。

当用户主动写日记、复盘一天或用语音输入记录真实生活时，把它视为 L5 人类真实行为层。L5 是现实锚点，不是普通聊天印象；原文默认本地私密，摘要经过准入后才进入长期记忆。

与 DIKWP 对齐时，P 是 Purpose（意图/目的），不是 Pattern。Pattern 是从 Data/Information 中抽取并在 Knowledge 中稳定下来的模式，不应替代 Purpose。

DIKWP 是语义认知层：

| DIKWP | Agent 含义 | 核心问题 |
|---|---|---|
| Data | 原始信号、日志、消息、工具输出 | 信号是什么？来源是什么？ |
| Information | 被 Purpose 筛选出的差异和关联 | 当前什么差异值得注意？ |
| Knowledge | 结构、规则、可验证解释 | 什么规律能解释或预测？ |
| Wisdom | 结合价值、风险、长期目标的判断 | 什么选择更合适？ |
| Purpose | 目标、动机、成功标准 | 为什么做？做到什么才算好？ |

认知治理是运行时治理层：它决定 DIKWP 产物应该留在痕迹、事件、断言、事实、知识、流程、身份、滋养还是 L5 行为层中。

## 分类阶梯

| 层级 | 问题 | 例子 | 行动 |
|---|---|---|---|
| 痕迹 | 发生了什么？ | 日志、工具输出、原始消息 | 存为证据或丢弃 |
| 事件 | 当时上下文是什么？ | 一次任务、一次故障、一个群聊线程 | 存为可重建记忆 |
| 断言 | 什么可能是真的？ | “用户不喜欢 X” | 暂存，等待检查 |
| 事实 | 现在应该相信什么？ | 活跃偏好、当前配置 | 带来源和新鲜度保存 |
| 知识 | 哪个规律可迁移？ | 架构原则、因果经验 | 写成可复用解释 |
| 流程 | 下次具体怎么做？ | SOP、skill、checklist | 做成可执行、可验证行为 |
| 身份 | agent 应该成为什么？ | 语气、边界、policy | 慢慢改，明确改 |
| 滋养 | 用户是否因此成长？ | 懂我、知我、接我、解我、养我 | 让用户更清醒、更有力量 |
| L5 行为 | 用户现实里发生了什么？ | 日记、语音转写、行动、回避、能量、反馈 | 作为现实锚点，原文本地，摘要准入 |

## 工作流程

1. **声明 Purpose。** 当前目标、成功标准、约束和反馈信号是什么？
2. **收集 Data。** 判断它来自用户、工具、日志、频道、模型推理，还是外部文档。
3. **提取 Information。** 在当前 Purpose 下，哪些差异、关联或异常值得注意？
4. **形成候选 Knowledge。** 哪些结构、规律或解释可以复用？证据是否足够？
5. **做 Wisdom 检查。** 是否考虑长期目标、用户偏好、伦理、安全、关系和风险？
6. **做滋养检查。** 这会让用户更清楚、更有能量、更能判断和行动吗？
7. **做 L5 检查。** 这是用户主动写下的真实行为日记吗？原文是否应保持本地私密？
8. **先分类。** 用治理阶梯判断它是痕迹、事件、断言、事实、知识、流程、身份、滋养，还是 L5 行为。
9. **检查权威。** 用户确认、工具观察、外部来源、模型推理的权威性不同。
10. **检查新鲜度。** 标记为当前、历史、未知或 timeless。
11. **检查用途。** 只保留能改善未来注意力、联想、行动或反馈评估的内容。
12. **选择表面。**
   - 原始证据进 trace store
   - 上下文重建进 episode/session store
   - 当前承认断言进 fact store
   - 可迁移模型进 knowledge doc
   - 可重复动作进 skill/SOP
   - 慢变量进 identity/policy file
   - 关系与滋养原则进 relationship manual
   - 用户日记进 L5 diary store
13. **写最小持久形式。** 优先写带来源的短句，不要粘贴长 transcript；日记原文默认不外发。
14. **添加退休规则。** 说明何时过期、复查或降级。
15. **测试检索。** 确保下一个 agent 在触发场景出现时找得到。
16. **闭环反馈。** 记录未来结果如何确认或修正 Purpose、Knowledge、行动策略、滋养方式或真实行为节奏。

## 准入门

把任何内容提升到事实、知识、流程或身份前，先问：

- 有没有模型直觉之外的证据？
- 现在还适用吗？
- 是否具体到能指导行为？
- 能安全泛化吗？
- 是否和更新的真相来源冲突？
- 如果被质疑，agent 能找回证据吗？

如果答案不清楚，就保留为候选断言或事件记忆，不要升为事实。

## 反馈处理

把反馈当成信号，不要当成自动更新。

可以吸收的反馈：

- 具体
- 重复出现或信号很强
- 绑定到可观察结果
- 对未来行为有用
- 可以安全泛化

不要吸收的反馈：

- 只有情绪，没有行动信号
- 绑定在过期状态上
- 被 live evidence 反驳
- 太私密或太原始，不适合长期保存

## 反模式

- 把原始聊天保存成长期真相
- 把旧 summary 当当前事实
- 把所有 memory 都加载到活跃上下文
- 因为一次情绪化纠正就永久改变身份
- 让频道行为变成核心认知
- 流程还不可重复就创建 skill
- 写出不能指导未来行动的知识
- 把“懂我”停留在安慰话术，而没有让用户变清楚、变强
- 为了制造陪伴感，让用户更依赖而不是更自由
- 把日记原文当成可随便外发或长期暴露的普通上下文
- 把某一天的情绪、失败或冲动永久写成用户身份

## 输出格式

当用户要求把一段对话或事件转成持久认知时，返回：

```text
分类：
- 痕迹：
- 事件：
- 候选断言：
- 权威事实：
- 可迁移知识：
- 流程 / 技能：
- 身份 / 规范：
- 滋养 / 成长：
- L5 人类真实行为 / 日记：

准入：
- 提升：
- 保持临时：
- 仅归档：
- 拒绝：

要写入的 artifact：
- ...

退休 / 复查：
- ...
```
