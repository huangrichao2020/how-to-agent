# how-to-use-agent v2

通过对话教会你的 Agent 进化 — 基于 Hermes 生产级架构。

> 把 Agent 当作能学习的新手系统，但前提是：你必须让学习变成
> 持久的架构、操作手册和可重复的习惯。

## 这不是框架

这是一条**提示词路径**：一段真实的人类指令序列，让 Agent 从"去研究这些项目"
变成"归档设计、讨论风险、谨慎落地第一步，并为未来的 Agent 写好操作手册"。

## v2 做了什么升级

基于**生产级 Agent 运行时**（Hermes）的实际运行经验：

- **TTSR 触发协议**：Agent 默认只加载锚点规则（~500 token），匹配触发词才注入对应技能/本能，用完释放。
- **gbrain 知识图谱**：每个架构决策、技能、记忆都以页面形式存储，带标签、时间线、链接。下一个 Agent 能遍历图谱。
- **同意闸门**：修改 Agent 自有表面（记忆、技能、提示词、配置）前，必须列文件、说风险、给回滚方案，然后请求批准。
- **失败升级协议**：3 步 — 读报错 → 探环境 → 换策略/问用户。绝不盲目重试。
- **自愈浏览器**：Agent 在运行时写/修补提取函数，不用死板框架。
- **Cron + 技能进化**：定时任务每天用 8 维度评分自动改进技能。学习会复利。

## 核心循环

```
外部信号
  → 源码级研究（适配备忘录）
  → 架构归档（gbrain 页面）
  → 顺序讨论
  → 风险/收益审查
  → 渐进式上线
  → 冻结相邻系统
  → 小步落地
  → 验证
  → 工作手册
  → 归档路径（gbrain slug + wiki URL）
```

## 怎么用

### 第一步：源头学习

```text
研究 [项目A] 和 [项目B]。
不要照搬。提取适合我们约束（2GB 内存、国内网络）的模式。
返回适配备忘录：有用模式、不兼容部分、最小实验。
```

### 第二步：架构优先

```text
这是大改动。先归档为 gbrain 页面。
然后我们一条条讨论。打上相关标签。
```

### 第三步：渐进上线

```text
在做最诱人的选项之前，对比直接切换 vs 渐进上线。
列出风险和回滚。迁移期间哪些子系统要冻结？
```

### 第四步：落地第一步

```text
开始第一步。复用现有逻辑。小心谨慎。
如果要修改 Agent 自有数据（记忆、技能、提示词），
先给我看：文件、风险、回滚 — 然后等批准。
```

### 第五步：写手册

```text
落地后，在架构设计旁边写工作手册。
更新 gbrain 页面，加时间线条目，推到 wiki。
下一个 Agent 应该能找到，不用重新发现。
```

## 关键原则

1. **研究先于采纳** — 不盲目照搬
2. **架构先于迁移** — 改代码前先写下来
3. **顺序先于速度** — 对有状态的 Agent，顺序就是正确性
4. **风险审查先于切换** — 对比直接 vs 渐进
5. **专注即安全** — 迁移期间冻结相邻子系统
6. **文档先于闭环** — 下一个 Agent 能找到才算完成
7. **修改前必同意** — Agent 自有表面需要明确批准

## 不要做的事

- 不要让 Agent"变聪明"而不给它一个要写的产物
- 不要让研究在同一句话里变成实现
- 不要同时改记忆、工具、提示词和运行时连线
- 设计、变更日志、延续路径不可找之前不要接受"完成"
- 不要因为外部项目看起来高级就照抄
- 不要让已完成的工作只存在于聊天记录里
